# CLAUDE.md

Инструкции для Claude Code по проекту.

## О проекте

Веб-сервис для отделений медицинской реабилитации (первое отделение — ОМР №4). Он автоматизирует:
- формирование «Индивидуальной программы медицинской реабилитации» (карты пациента) из листа назначений, расписания групп ЛФК и бассейна;
- подбор индивидуальных занятий и тренажёров в свободные «окна» пациента с равномерной нагрузкой на инструкторов.

Карта печатается, отметки о проведённых занятиях персонал ставит от руки. Интеграций и API с МИС нет.

Документация — в `docs/`:
- `docs/02-stack.md` — стек;
- `docs/TZ.md` — техническое задание (v2.1: программы, импорт листа назначений, карта).

Блок расписания переделывается в «расписание v2» (`docs/TZ.md` §7, согласовано 05.10.2026): индивидуальные — в шахматке на день вперёд, только будни. Текущий код `apps/scheduling` — первый прототип, автотестов у него нет; смены, постоянная занятость и вид сетки из него остаются.

Исходные документы заказчика лежат в `primary_docs/` (только для чтения, не изменять).

## Стек и версии

Согласовано (см. `docs/02-stack.md`): Python 3.12+, Django 5.2 LTS, PostgreSQL 16+, шаблоны Django + HTMX + Alpine.js, Bootstrap 5 (всё локально, без CDN), openpyxl, python-docx, django-simple-history, pytest. Деплой (фаза 5) — Docker Compose (nginx + gunicorn + PostgreSQL) на сервере клиники.

**MS Excel — основной редактор таблиц в организации.** Все правки вносятся в веб-системе, а выгруженный `.xlsx` нужен для печати из MS Excel. Выгрузка должна корректно открываться в MS Excel; даты и время записываются настоящими значениями Excel.

Точные версии зафиксированы в `pyproject.toml` (`[dependency-groups]`, `==`). Новая зависимость добавляется туда же с точной версией.

## Стиль кода

- ruff — и линтер, и форматтер; длина строки 100. Перед сдачей работы: `ruff format . && ruff check .` без ошибок.
- Аннотации типов в сигнатурах обязательны; mypy не используем.
- Идентификаторы — на английском. Комментарии, docstring, тексты для пользователя и сообщения об ошибках — на русском.
- Комментарии объясняют «почему», а не «что». Ссылки на требования — в виде `TZ.md, FR-XXX-N`.
- Доменная логика (`domain/`, а также `apps/cards/xlsx/`) — чистый Python без импортов Django: dataclass на входе, результат на выходе.
- Права и бизнес-правила проверяются в сервисах (`services.py`), представления остаются тонкими.
- Имена: модели — единственное число (`Admission`, `Booking`); сервисы — глаголы (`apply_proposal`); шаблоны — `templates/<app>/<screen>.html`; management-команды — `snake_case` по действию.
- Ошибки, которые видит пользователь, — отдельные исключения с понятным русским текстом (пример: `CardRenderError`).

## Запуск и отладка

Только локальная разработка: `.venv` + PostgreSQL 16 на хосте. Docker и прод — в фазе 5.

```bash
python3 -m venv .venv                       # один раз (нужен пакет python3.12-venv)
.venv/bin/pip install --upgrade pip         # нужен pip ≥ 25.1 для --group
.venv/bin/pip install --group dev
cp .env.example .env                        # и поправить SECRET_KEY, DATABASE_URL
.venv/bin/python manage.py migrate
.venv/bin/python manage.py load_initial_catalog  # справочники из primary_docs (повторный запуск безопасен)
.venv/bin/python manage.py seed_dev         # пользователи admin / doctor / rehab и вымышленные инструкторы
.venv/bin/python manage.py load_board_instructors --since 2026-09-01 --replace  # для показа: настоящие инструкторы
                                            # и распорядок из primary_docs/instructions_schedule.xlsx (согласие есть)
.venv/bin/python manage.py load_demo_board   # для показа: пациенты и шахматка как на primary_docs/plan.jpg
                                            # (удаляет всех пациентов; после load_board_instructors)
.venv/bin/python manage.py runserver
```

- База: `postgres://omr4:omr4@localhost:5432/omr4`, у роли `omr4` есть `CREATEDB` (для тестовой базы).
- Тестовые пользователи `seed_dev`: `admin`, `doctor`, `rehab`, пароль `devpass123`, и вымышленные инструкторы (Волков/ Лебедева — пара 2/2). Команда работает только при `DEBUG=true`.
- Настоящие инструкторы (фамилии, пары, распорядок; пациенты из файла не читаются) — `load_board_instructors`; после неё `seed_dev` вымышленных не добавляет. В тестах — только вымышленные инструкторы `seed_dev`. Кто из пары 2/2 в какой день работает, в шахматке не видно — по умолчанию первый в подписи с `--since`, правится на экране «Смены».
- Справочники ведутся в админке. Доступ к ней (`is_staff` + группа «Специалист ФР») выставляет `apps/accounts/admin_access.py` по сигналу изменения `Membership` — вручную `is_staff` не ставить.
- Все страницы закрыты входом (`LoginRequiredMiddleware`); открытая страница помечается `@login_not_required`.
- Группы, бассейн и тренажёры пересобираются сами (`apps/scheduling/services.replan`) после импорта и любых изменений назначений и курса; закреплённые (`pinned`) занятия не трогаются. Индивидуальные — только в шахматке на день вперёд (`apps/scheduling/board_days`): шахматки на сегодня и следующий будний день создаются сами (`ensure_boards`) копированием предыдущей, расчёт дня — `domain/board_day.plan_day`, блоки «Не распределены»/«Отменены» — `BoardPatient`. `replan` в конце сверяет пациента с шахматками (`sync_program`). Порядок блокировок: программа → тренажёры → инструкторы → шахматки (`board_days.lock`, advisory lock).
- Сервисы сохраняют модели с историей через `instance._history_user = user`, чтобы автор попадал в журнал и вне веб-запроса.
- HTMX: действие возвращает фрагмент целиком (`hx-swap="outerHTML"`), ошибки форм — в том же фрагменте со статусом 200.
- На `<body>` включён `hx-boost`: ссылки на скачивание файлов и в админку — с `hx-boost="false"`. htmx не выполняет `<script>` из ответов (`allowScriptTags: false`): все скрипты подключаются только в `<head>` `base.html` и работают по наличию своих элементов на странице (как `board.js` с `#board`). CSRF для HTMX берётся из cookie (`static/js/live.js`).
- Реальное время (NFR-11): контейнер с `id` и `data-live="тема…"` обновляется сам; темы публикуют сигналы моделей (`apps/live/signals.py`), пакетные записи (`bulk_create`, `_raw_delete`) — явно через `apps.live.events.publish`.
- Права: `apps/accounts/access.py` (`has_role`, `has_role_anywhere` — для ресурсов центра, `require_role`, `departments_for`, `current_department`). Администратор — `is_superuser`, роли `doctor`/`rehab` — через `Membership`.
- Все настройки — в `config/settings.py`, значения — из `.env` (образец — `.env.example`). Отдельных файлов dev/prod нет.
- Выбытие (`TZ.md`, FR-PRG-9): `programs.services.withdraw` / `restore`, запись `Withdrawal`. Дни отсутствия — `Program.gaps` (кэш на экземпляре), их учитывают `is_therapy_day` и `withdrawn_on(day)` для запросов; дальше всё делает `replan`.
- Повторный курс (FR-PRG-10): `Program.previous`, `programs.services.find_previous_courses` / `copy_plan` / `link_previous` / `patient_courses`; импорт останавливается `PreviousCoursesFound`, пока не выбран `Plan` (`exchange/services.py`), разобранный лист ждёт в сессии (`exchange/views.py`).
- Правка индивидуальных — только в шахматке (`apps/scheduling/board.py`: `place_patient`, `move_patient`, `remove_patient`), правка сегодняшней переходит на завтра (`board_days.propagate`). После изменения смены/распорядка — `apps/scheduling/staff_changes` (пациенты уходят в «Не распределены»). `manual.py` — правка групп и тренажёров на странице программы.
- Экран «Распорядок» (`staff:duties`) — сетка инструкторы × слоты на дату, как «Смены»: клик «кистью» (вид, постоянно с даты / только на дату) — `board.paint_duty` поверх тех же `add_duty`/`end_duty`/`add_block`/`clear_block`, что у панели ячейки шахматки. Распорядок — только в часы смены (`staff/domain.shift_hours`: 2/2 — 8:00–20:00, остальные — 8:00–17:00).
- Публичная шахматка `/board/` открыта без входа (`@login_not_required`), сети — `PUBLIC_BOARD_NETWORKS`.
- Прототипы карт: `.venv/bin/python manage.py card_prototype` → `out/`.
- Пересобрать шаблоны карт из `primary_docs/programm_template.xlsx`: `.venv/bin/python manage.py extract_card_templates`.
- Не делать коммитов без просьбы.

## Тесты

- pytest + pytest-django, тесты идут на настоящем PostgreSQL (тестовая база создаётся автоматически).
- Запуск: `.venv/bin/pytest`; с покрытием: `.venv/bin/pytest --cov=apps --cov-report=term-missing`.
- Несколько прогонов одновременно (например, агенты) — каждому свою тестовую базу:
  `DATABASE_URL=postgres://omr4:omr4@localhost:5432/omr4_<имя> .venv/bin/pytest -p no:cacheprovider`.
- Листы назначений в тестах — только из `tests/sheets.py` (вымышленные данные); `primary_docs/pacient.docx` в тестах не используется.
- Покрытие `domain/`, `apps/cards/xlsx/` и `exchange/` — не ниже 90 %, для сервисов — ключевые сценарии и права (TZ.md, NFR-9).
- Тесты лежат в `tests/<app>/`, повторяя структуру `apps/`.
- Новая функция сдаётся вместе с тестами. Для выгрузок xlsx файл читается обратно через openpyxl и проверяются значения, типы и форматы.

## Глоссарий предметной области

| Термин | Значение |
|---|---|
| ОМР | Отделение медицинской реабилитации (ОМР 1, ОМР 3, ОМР 4…) |
| ШРМ | Шкала реабилитационной маршрутизации: 3, 4 или 5. Определяет длительность курса: ШРМ3 — 10 дней, ШРМ4 — 14, ШРМ5 — 20 (в карте 11 / 15 / 20 календарных дат, считая день поступления) |
| Индивидуальная программа | Главная сущность системы (`Program`): программа реабилитации пациента на один курс — данные из листа назначений, назначения и расписание. Печатается как карта. Выписки и истории болезни в системе нет |
| Лист назначений | Документ врача (Word или выгрузка МИС): ФИО, ИБ, ШРМ, диагноз, палата, назначения. Для карты нужна колонка «Физиотерапия» |
| ИБ | Номер истории болезни |
| ЛФК | Лечебная физкультура; групповые занятия идут по фиксированному расписанию (`lfk.xlsx`) |
| ЛФК в воде / бассейн | Групповые занятия по типу: верхняя конечность, нижняя конечность, спина (`basseyn.xlsx`). Группа выбирается по назначению врача и времени её занятия |
| Инд., инд. занятие | Индивидуальное занятие с инструктором (30 мин); не больше 2 в день, лимит задаёт врач |
| Шахматка | Ежедневное расписание инструкторов (`instructions_schedule.xlsx`, один лист на день) |
| «Nп Фамилия» | Запись пациента в шахматке: N — номер палаты, «а» — вариант палаты (5а) |
| «Метод. работа» | Слот инструктора, недоступный для пациентов |
| «Паршуков/ Ким» | Два инструктора в одной колонке, которые работают по графику 2/2 |
| Тренажёры st (ST-150), Имитрон, Pablo | Работают только с 13:00 до 15:00, процедура 15 мин, вместимость у каждого своя |
| БОС | Биологическая обратная связь (кабинет/зона БОС-терапии) |
| Группы | Эрго общая, Вестибулярная гимнастика, I can нога, I can рука, Нейро-тренинг, Лого-тренинг, Эрготерапия, Логоритмика, Эрго-кисть. Ограничения по вместимости нет |
| art, (шар) | Уточнения к занятию (методика или инвентарь) — пометка в ячейке шахматки; отдельно не планируются |
| Мото-Л, Артромот | Отдельная строка листа назначений; это одно из индивидуальных пациента, только вечером (с 18:00) у инструкторов 2/2; в карте отдельной строки нет |
| PNF, RC, HUR | Методики индивидуальных занятий; инструктор пишет их в карте рукой, в системе не хранятся |
| Бассейн | Не связан с шахматкой инструкторов ЛФК: важны группа и время, а не инструктор |
| ДС, группы ДС | Групповые занятия дневного стационара (`Gruppy_DS.xlsx`, вид `DS_GROUP`): острая спина, спина, плечо, коленный сустав, ШОП (шейный отдел позвоночника), ТБС (тазобедренный сустав), ГСС (голеностопный сустав). Назначаются пациентам любого отделения; как бассейн — не связаны с инструкторами. В листе назначений ищутся последними (`exchange/matching.py`, `FALLBACK_KINDS`) |
| Только строка в карте | Tigo, Алмаг, Степпер, массаж, Орторент-дорожка, консультации эрготерапевта, психолога и логопеда — без времени, только строка для подписей |
| Выходные | Занятия идут 7 дней в неделю; проводят инструкторы со сменами 2/2 (8:00–20:00); расписание групп каждый день одинаковое. Шахматка индивидуальных — только по будням |
| Дни занятий | Курс без дня поступления и дня выписки: в эти дни у пациента занятий нет совсем |
