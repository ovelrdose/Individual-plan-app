## 1. Цель и границы

### 1.1. Цель
Убрать ручное копирование при составлении «Индивидуальной программы медицинской реабилитации». Система — это **список индивидуальных программ**. Каждая программа:
1. создаётся из листа назначений врача: врач загружает свой `.docx` (тот же шаблон, что он ведёт для письменной документации), назначения появляются в вебе, при необходимости врач правит их там же — без повторной загрузки файла. Ручной ввод — запасной путь;
2. сама получает расписание: групповые занятия ЛФК и бассейн — по расписанию групп, тренажёры — по окну тренажёров на весь курс; индивидуальные занятия — в ежедневной шахматке инструкторов, которая составляется на день вперёд с равномерной нагрузкой на инструкторов (§7);
3. индивидуальные занятия правятся вручную прямо в шахматке;
4. выгружается в `.xlsx` по шаблону карты для печати из MS Excel.

По итогам проверки первого прототипа (05.10.2026) расписание переделано в «расписание v2» (§7).

Расписания, из которых строятся программы, тоже ведутся в вебе, а не в Excel: расписание групп ЛФК и бассейна, окна тренажёров, смены и распорядок инструкторов, шахматка. Система — не МИС: выписки, истории болезни и медицинских данных сверх нужного для программы в ней нет. Отделений — сколько угодно.

### 1.2. Входит
Всё, что описано в §4–§9 (§7 — после согласования новой версии).

### 1.3. Не входит
- Интеграция и API с МИС, обмен с внешними системами.
- Электронные отметки о проведении занятий (отметки ставятся от руки на распечатке).
- Обратная загрузка правок из Excel (Excel только для печати).
- Методики индивидуальных занятий (PNF, RC, HUR) — их пишет инструктор от руки.
- Расписание по времени для Tigo, Алмага, Степпера, массажа, Орторент-дорожки, консультаций эрготерапевта, психолога и логопеда — для них только строка в карте.
- Учёт инструкторов бассейна.
- Лекарственные и диагностические назначения из листа назначений.
- Мобильное приложение. Достаточно веб-интерфейса для десктопа (ширина от 1280 px).

## 2. Термины

См. глоссарий в `CLAUDE.md`. Дополнительно:
- **Индивидуальная программа (Program)** — программа реабилитации пациента на один курс: данные из листа назначений, назначения и расписание. Повторное поступление того же человека — новая программа.
- **Курс** — даты программы: `start_date … start_date + course_days[ШРМ] − 1`, календарные дни.
- **Типичный день** — расписание, которое печатается в верхнем блоке карты «Расписание занятий» (время | процедура | место).
- **Бронирование (Booking)** — занятие пациента в конкретную дату и время.
- **Дни занятий** — курс без дня поступления и дня выписки (`start_date + 1 … end_date − 1`): в эти два дня у пациента нет никаких занятий.
- **Шахматка на дату (BoardDay)** — индивидуальные занятия всех инструкторов на один будний день. Составляется на день вперёд (§7).
- **Постоянная занятость** — распорядок инструктора и разовые блоки (метод. работа, ведение группы, БОС, прочее): в этот слот индивидуальные не ставятся.

## 3. Пользователи и роли

| Роль | Код | Кратко |
|---|---|---|
| Администратор | `admin` | Всё, включая отделения, пользователей, справочники; удаление программ и пользователей |
| Врач | `doctor` | Индивидуальные программы своих отделений: импорт листа назначений, правка данных и назначений, выгрузка карты. Расписание — только просмотр |
| Специалист по физической реабилитации | `rehab` | Формирует и правит расписание программ; справочники, выгрузки. Данные и назначения — просмотр |

Других ролей нет. **Все сотрудники отделения видят все программы этого отделения** (решение владельца 04.10), независимо от того, кто их создал.

| Действие | Админ | Врач | Специалист ФР |
|---|---|---|---|
| Отделения, пользователи | ✓ | — | — |
| Справочники | ✓ | — | процедуры, группы, тренажёры, инструкторы (без удаления) |
| Создавать и править программу и назначения | ✓ | ✓ (своё отделение) | просмотр |
| Расписание программы | ✓ | просмотр | ✓ |
| Удаление программ и пользователей | ✓ | — | — |
| Выгрузка карты | ✓ | ✓ | ✓ |

Права проверяются в сервисах: роль + членство в отделении. Требования:
- **FR-ACC-1.** Вход по логину и паролю, выход, смена пароля пользователем, сброс пароля администратором. Сессия завершается после 8 часов бездействия (параметр).
- **FR-ACC-2.** Пользователь состоит в одном или нескольких отделениях, в каждом — со своей ролью (`Membership`). Пациентов отделения, в котором он не состоит, пользователь не видит (ни в списках, ни по прямой ссылке → 404).
- **FR-ACC-3.** У пользователя есть поле `short_name` («Петлина К.И.») — оно печатается в карте как врач.
- **FR-ACC-4.** Права проверяются на уровне сервисов (сервис получает пользователя и проверяет роль и отделение), а не только в шаблонах.
- **Критерий приёмки:** тесты на права для ключевых операций (создать программу, править назначения, выгрузить карту, удалить программу).

## 4. Справочники (catalog, staff, org)

Справочники редактируются в админке Django (у роли `rehab` — доступ к своему подмножеству, решение 13). Удаление используемых записей запрещено, вместо него — флаг `is_active`.

### 4.1. Отделения
- **FR-ORG-1.** `Department`: название («ОМР № 4»), код, `course_days` (по умолчанию `{3: 11, 4: 15, 5: 20}`), `max_individual_per_day` (по умолчанию 2), `is_active`.
- **FR-ORG-2.** Новое отделение добавляется без изменения кода.

### 4.2. Процедуры
- **FR-CAT-1.** `Procedure`: `name`, `card_label`, `synonyms` (список строк), `kind` ∈ {`LFK_GROUP`, `DS_GROUP`, `POOL`, `INDIVIDUAL`, `EQUIPMENT`, `CARD_ONLY`}, `default_duration_min`, `place`, `equipment` (для `EQUIPMENT`), `department` (null = для всего центра), `is_active`. Порядок строк в карте задаёт назначение, а не процедура (FR-PRG-3).
- **FR-CAT-2.** Для бассейна: процедура «Бассейн» (`POOL`, признак `group_choice` — «тип не указан», своего расписания у неё быть не может) и процедуры групп бассейна «ЛФК в воде: верхняя конечность / нижняя конечность / спина» (`POOL`, с сессиями).
- **FR-CAT-2a. Группы дневного стационара** (`DS_GROUP`, `Gruppy_DS.xlsx`): острая спина, спина, плечо, коленный сустав, ШОП, ТБС, ГСС — 30 мин, место — кабинет из файла. Общие для центра: назначаются пациентам любого отделения. Подбираются как группы ЛФК и бассейн (FR-SCH-2); с инструкторами и шахматкой не связаны — как бассейн (в «Ведении группы» их нет).

### 4.3. Расписание групп
- **FR-CAT-3.** `GroupSession`: `procedure`, `start_time`, `duration_min`, `place`. Расписание одинаково каждый день недели. У процедуры может быть несколько сессий в день. Ограничения по вместимости нет.
- Длительность по умолчанию: ЛФК — 30 мин, группы ДС — 30 мин, бассейн — 30 мин (подтверждено, ответ 5; остаётся параметром).

### 4.4. Тренажёры
- **FR-CAT-4.** `Equipment`: `name`, `window_start` (13:00), `window_end` (15:00), `step_min` (15), `capacity` (по умолчанию 1, настраивается), `duration_min` (15), `is_active`. Возможные начала: `window_start + k·step_min`, при этом `start + duration ≤ window_end`.
### 4.5. Сетка слотов инструкторов
- **FR-CAT-5.** Сетка слотов (одна на центр): записи `InstructorSlot` `(start, end)` по порядку времени. По умолчанию: 09:10–09:40, 09:50–10:20, 10:30–11:00, 11:10–11:40, 13:00–13:30, 13:40–14:10, 14:20–14:50, 15:00–15:30, 15:40–16:10, 16:20–16:50, 18:00–18:30, 18:40–19:10, 19:20–19:50. Вечерние слоты имеют флаг `evening` и не печатаются в карте.
- Слот — запись `InstructorSlot` (начало, конец, «вечерний»); бронирования и блоки ссылаются на неё внешним ключом (`slot`), а не на позицию в списке. Слот с бронированиями нельзя удалить (`PROTECT`), а менять его время запрещает сервис со списком конфликтов.

### 4.6. Инструкторы и смены
Понравилось на проверке прототипа и остаётся без изменений.
- **FR-STF-1.** `Instructor`: `full_name`, `short_name`, `partner` (симметричная связь: если у A напарник B, то у B напарник A — поддерживается сервисом), `display_order`, `is_active`.
- **FR-STF-2.** `ShiftPattern`: `instructor`, `pattern` ∈ {`2/2`, `5/2`, `daily`}, `anchor_date`, `valid_from`, `valid_to`. Для `2/2`: рабочий день, если `(date − anchor_date).days mod 4 ∈ {0, 1}`. Для `5/2`: понедельник–пятница. Инструкторы 2/2 работают 12 часов (8:00–20:00) — только у них есть вечерние слоты (FR-SCH-8).
- **FR-STF-3.** `ShiftException`: `instructor`, `date`, `is_working`, `reason`. Исключение важнее шаблона.
- **FR-STF-4.** Экран «Смены»: календарь месяца, строки — инструкторы, ячейки — рабочий или нерабочий день (как `Лист3` в `instructions_schedule.xlsx`). Клик по ячейке создаёт или удаляет исключение.
- **FR-STF-5. Постоянная занятость.** Специалист ФР задаёт, что инструктор делает в слоте каждый свой рабочий день (`InstructorDuty`): ведёт группу (из расписания групп), БОС, «Метод. работа», прочее — с периодом действия `valid_from…valid_to`. На конкретную дату распорядок можно снять или заменить разовым блоком (`InstructorBlock`). В слоте с постоянной занятостью индивидуальных нет — ни автоматически, ни вручную. Распорядок и блоки ставятся и в панели ячейки шахматки. Экран «Распорядок» — сетка на дату, как «Смены»: строки — инструкторы, столбцы — слоты; выбирается вид («Метод. работа», ведение группы, БОС, прочее, «Свободно») и как ставить — постоянно с даты или только на эту дату; клик по ячейке ставит, повторный клик тем же видом снимает. Распорядок ставится только в часы смены: 2/2 — 8:00–20:00, 5/2 — 8:00–17:00.
- **FR-STF-6.** Отметка «не работает» на дату (`ShiftException`) ставится в шахматке или на экране «Смены» одним действием. Пациенты этого инструктора на эту дату уходят в «Не распределены» (FR-SCH-6).
- **Критерий приёмки:** unit-тесты `is_working()` для 2/2, 5/2, daily, исключений и границ `valid_from`/`valid_to`.

### 4.7. Начальное наполнение
- **FR-CAT-6.** Management-команда `load_initial_catalog` загружает:
  - группы ЛФК и их сессии из `lfk.xlsx`;
  - группы бассейна из `basseyn.xlsx`;
  - группы дневного стационара из `Gruppy_DS.xlsx` (колонка C — место проведения);

  - процедуру «Индивидуальное занятие» (`INDIVIDUAL`, 30 мин);
  - сетку слотов;
  - отделение «ОМР № 4».

  Синонимы задаются в фикстуре (см. §6.2). Команда идемпотентна.
- Время в `lfk.xlsx` и `basseyn.xlsx` хранится как доля суток (`0.381944…` = 09:10) — конвертировать с округлением до минуты.

## 5. Индивидуальные программы (programs)

- **FR-PRG-1.** `Program`: `department`, `full_name`, `sex` (М/Ж, может быть пустым), `age` (целое, необязательное), `history_number` (ИБ, необязательный), `room` (строка: «9», «5а»), `shrm` ∈ {3, 4, 5}, `diagnosis` (необязательный), `attending_doctor` (FK User), `start_date`, `end_date`, `end_date_manual`, `source` ∈ {`import`, `manual`}, `import_warnings` (список строк), `created_at`, `updated_at`. История изменений — NFR-5.
- **FR-PRG-2.** `end_date` по умолчанию: `start_date + course_days[shrm] − 1`. Врач может изменить её — это продление или досрочное окончание программы (`end_date_manual = true`), дальше она не пересчитывается. Если дату не меняли вручную, она пересчитывается при смене ШРМ или даты начала. Даты назначений должны помещаться в курс — иначе сохранение отклоняется со списком назначений, которые нужно поправить.
- **FR-PRG-3.** `Prescription`: `program`, `procedure` (пусто — строка не распознана), `raw_text` (строка из листа назначений), `duration_min`, `per_day`, `start_date` / `cancel_date` (пусто — с начала / до конца курса; `cancel_date` — первый день без процедуры, не позже `end_date`), `in_card`, `card_order` (порядок строк в карте = порядок назначений, врач может переставить).
  - Для `INDIVIDUAL`: `per_day` не больше `max_individual_per_day` отделения; импорт урезает больше лимита до лимита с предупреждением.
  - Для `LFK_GROUP` и `POOL`: `per_day` — сколько раз в день пациент ходит в **эту** группу. Импорт всегда ставит 1 (FR-IMP-3); больше врач ставит вручную, если группа идёт несколько раз в день (Нейро-тренинг в 10:30 и 14:20).
  - Для `POOL` с процедурой «Бассейн» (группа не указана) группу бассейна выбирает специалист ФР в блоке «Расписание» программы: список групп с временем их занятий. Выбор хранится в `pool_group` назначения, запись врача «Бассейн» не меняется; после выбора расписание пересобирается сразу. Выбор можно сменить или снять.
- **FR-PRG-4.** Экран **«Индивидуальные программы»** (главный): ФИО, палата, ШРМ, даты курса, врач, состояние программы — «требует проверки» (есть предупреждения импорта или нераспознанные назначения), затем «расписание не составлено / составлено / есть конфликты» (с фазы 2). Фильтр: текущие (курс не закончился и пациент не выбыл) / завершённые (в том числе выбывшие) / выбывшие / все. Поиск по ФИО и ИБ без учёта регистра и «ё». Порядок — по номеру палаты.
- **FR-PRG-5.** Создание: главная кнопка — **«Загрузить лист назначений»** (§6); запасная — «Создать вручную» (форма тех же полей). На экране загрузки отделение видно и выбирается явно (по умолчанию — из шапки; предлагаются отделения, где пользователь врач); после загрузки шапка переключается на это отделение.
- **FR-PRG-8.** Удаление программы — только администратор, со страницей подтверждения; вместе с программой удаляются назначения, расписание и журнал выгрузок, запись об удалении остаётся в истории. Удаление пользователей — администратор в админке; лечащего врача программ удалить нельзя, пока программы не переданы другому врачу (или пользователь просто отключается).
- **FR-PRG-6.** Страница программы — это и есть программа: шапка (данные пациента, курс, врач), блок «Проверьте после импорта» (предупреждения; врач закрывает его кнопкой), **назначения** (правка, удаление, порядок, смена процедуры у нераспознанной строки), **расписание** (типичный день и календарь курса; индивидуальные — из шахматки, §7), кнопка **«Скачать карту»** (§8).
- **FR-PRG-7.** Выписки нет. Программа завершена, когда её курс закончился, или пациент выбыл (FR-PRG-9). Продление или исправление плана — правка даты окончания; уход пациента раньше срока — выбытие. Завершённые программы остаются в списке (фильтр) и доступны для выгрузки.
- **FR-PRG-9. Выбытие** (решение 62). Пациент закончил раньше срока: досрочная выписка, отказ, перевод, самовольный уход, другое (+ необязательный комментарий).
  - Отмечают врач и специалист ФР отделения пациента и администратор. Запись `Withdrawal`: `date_from` — первый день без занятий (по умолчанию сегодня; со второго дня курса до дня перед выпиской), `reason`, `note`, `returned_on` — с какого дня пациент восстановлен. Плановая `end_date` не меняется; открытое выбытие у программы одно.
  - С `withdrawn_on` у пациента нет занятий: удаляются все записи с этой даты (группы, бассейн, тренажёры, индивидуальные), пациент уходит из шахматок, в том числе из блоков «Не распределены» и «Отменены», подбор и составление следующей шахматки его не учитывают. Если отмечено днём — сегодняшние занятия убираются целиком. Прошедшие дни не меняются.
  - Назначения и данные выбывшего — только просмотр; на странице программы и в списке — отметка «Выбыл ДД.ММ (причина)».
  - **Восстановление** — те же роли, пока не прошла плановая `end_date`: `returned_on` = сегодня, дни отсутствия остаются без занятий (выбытие, которое ещё не наступило или поставлено сегодня, просто снимается); группы, бассейн и тренажёры подбираются заново с сегодняшнего дня, в завтрашнюю шахматку пациент ставится автоматически как новый, в сегодняшнюю — в «Не распределены». Ручные правки после даты выбытия не возвращаются. Это продолжение той же программы до плановой `end_date`: пропущенные дни не компенсируются, продлить курс при необходимости врач может датой окончания (FR-PRG-2). Новый курс — новая программа (FR-PRG-10). После плановой `end_date` программа выбывшего — в архиве, восстановить нельзя.
  - Карта выбывшего: даты начиная с `withdrawn_on` заштрихованы, к строке пола и возраста добавляется «выбыл ДД.ММ».
- **FR-PRG-10. Повторный курс** (решение 63). Пациенты приезжают повторно; ИБ каждый раз новый, поэтому прошлые курсы ищутся по ФИО (без учёта регистра, «ё» и лишних пробелов) среди завершённых программ отделения, совпадение подтверждает пользователь (однофамильцы возможны).
  - При импорте листа (FR-IMP-13) и при ручном создании, если найден прошлый курс, — выбор: **«Создать по новому листу»** (по умолчанию) или **«Взять прошлый план»**: назначения прошлого курса (процедура, длительность, частота, «в карту», порядок, группа бассейна); ИБ, палата, ШРМ и даты — из нового листа или формы. Даты назначения и отмены не переносятся.
  - При ручном создании выбор — в той же форме: «Взять прошлый план», «Новые назначения, курс связать с прошлым» или «Это другой пациент».
  - На странице завершённой (или выбывшей) программы — кнопка «Повторный курс»: форма с данными пациента (без ИБ) и новой датой начала, по умолчанию — «Взять прошлый план». Пока курс идёт, повторный не создаётся.
  - Прошлый курс — программа отделения с тем же ФИО, закончившаяся до начала нового или выбывшая до него; выбывшая с пересекающимися датами — прошлый курс, а не дубль (FR-IMP-11).
  - Новая программа ссылается на прошлую (`previous`); на странице программы — список «Курсы пациента». Отдельной карточки пациента нет (система — не МИС).
- **Права** (§3): создавать, импортировать и править данные и назначения — врач отделения и администратор; специалист ФР — просмотр данных и назначений, правка расписания (§7).

## 6. Импорт листа назначений (.docx)

Главный способ создать программу. Образец — `primary_docs/pacient.docx` (шаблон, который врачи ведут для письменной документации).

### 6.1. Разбор документа
- **FR-IMP-1. Шапка** — первый абзац, содержащий `ФИО`. Поля:
  - `ФИО\s+(?P<fio>.+?)\s{2,}ИБ` (обязательно);
  - `ИБ\s*№\s*(?P<ib>\d+)`, `Диагноз:\s*(?P<dx>\S+)` (необязательно);
  - `ШРМ\s*(?P<shrm>[345])`, `Палата\s*№\s*(?P<room>\S+)` (обязательно).

  Если шапка встречается несколько раз и значения отличаются (в образце ИБ `5402` и `513402`) — берётся первое значение и записывается предупреждение со всеми вариантами.
- **FR-IMP-2. Физиотерапия** — первая таблица, в строке заголовка которой есть ячейка `Физиотерапия`. Из каждой следующей строки берутся: текст ячейки «Физиотерапия», дата в ячейке слева (`дд.мм.гг`) — дата назначения, дата в ячейке справа — дата отмены. Абзацы ячейки объединяются через перевод строки, пустые строки пропускаются.
- **FR-IMP-3. Группы.** Абзацы, начинающиеся с `-` (`–`, `—`), — перечисление групп внутри строки «Групповые занятия ЛФК». Каждая группа становится отдельным назначением с общей длительностью и частотой 1 р/д: «2 р/д» под списком — это сколько групповых занятий в день на весь список, т. е. каждая группа идёт один раз (решение 42). Если число в «р/д» не совпадает с числом групп в списке — предупреждение импорта; частоту группы врач может поправить в назначении.
- **FR-IMP-4.** Длительность: `(\d+)\s*мин` (включая «минут»). Частота: `(\d+)\s*р/д`.
- **FR-IMP-5. Консультации.** В колонке «Диагностические назначения» той же таблицы строка, начинающаяся с «Консультац», перечисляет специалистов через запятую («Консультация терапевта, медицинского психолога, медицинского логопеда, эрготерапевта…»). Каждый специалист сопоставляется со справочником по синонимам; совпавшие (психолог, логопед, эрготерапевт) становятся назначениями `CARD_ONLY`, остальные (терапевт и т. п.) пропускаются без предупреждения. Остальное содержимое колонки и таблицы лекарств не разбирается.
- **FR-IMP-6. Даты курса.** Дата начала программы — самая ранняя дата назначения в таблице. Назначение, начатое позже, получает `start_date`; отменённое — `cancel_date`. Дата окончания — по ШРМ (FR-PRG-2).
- **FR-IMP-7. Пол, возраст, врач.** В листе их нет:
  - пол определяется по отчеству (`…вич`/`…ич` → М, `…вна`/`…чна` → Ж); не определился — поле пустое и предупреждение;
  - возраст — необязательное поле, врач может дописать на странице программы; в карте без возраста печатается только пол;
  - лечащий врач — пользователь, загрузивший файл (если он врач отделения), иначе его выбирают на экране загрузки.

### 6.2. Сопоставление со справочником
- **FR-IMP-8.** Нормализация строки и синонимов: нижний регистр, `ё→е`, все виды тире и дефисов, пробелы и точки удаляются. Совпадение — синоним входит в нормализованную строку. Если подошло несколько процедур, побеждает самый длинный синоним. Нет совпадений → `procedure = null`, строка подсвечивается на странице программы.
- **FR-IMP-9.** Бассейн: строка содержит `бассейн` или `в воде`. Группа определяется по `верхн` / `нижн` / `спин`. Не найдена — процедура «Бассейн» (группу выберет специалист ФР).
- **FR-IMP-14. Группы ДС** узнаются по названию и сокращению в любом месте листа (в списке «Групповые занятия ЛФК» или отдельной строкой): «спина», «острая спина», «плечо / плечевой сустав», «колено / коленный сустав», «ШОП / шейный отдел позвоночника», «ТБС / тазобедренный сустав», «ГСС / голеностопный сустав» и их падежные формы (синонимы в справочнике). Группы ДС названы по части тела, а часть тела часто уточняет другую процедуру, поэтому они сопоставляются **последними** — только если строка не подошла ни к одной другой процедуре: «Массаж плечевого сустава» — Массаж, «Артромот коленного сустава» — Артромот, «Бассейн спина» — бассейн (FR-IMP-9), «ЛФК ШОП» — группа ДС. Среди групп ДС — самый длинный синоним: «острая спина», а не «спина».
- **Эталонные примеры** (обязательные тест-кейсы):

| Строка | Ожидаемый результат |
|---|---|
| `Групповые занятия ЛФК` / `- Эрго общая` / `- I can нога` / `30 мин 2 р/д е/д` | 2 назначения: `LFK_GROUP` «Эрго общая» и «I can нога», 30 мин, per_day 1 (две группы в день — каждая один раз), без предупреждений |
| `Групповые занятия ЛФК` / `- Эрго общая` / `30 мин 2 р/д` | `LFK_GROUP` «Эрго общая», per_day 1 + предупреждение «2 р/д на 1 группу» |
| `Индивидуальное занятие ЛФК 30 мин 1 р/д е/д` | `INDIVIDUAL`, 30 мин, per_day 1 |
| `Thera Trainer Tigo 15 мин 2 р/д е/д` | `CARD_ONLY` T.tigo |
| `Имитрон  15 мин 1 р/д е/д` | `EQUIPMENT` Имитрон, 15 мин |
| `ST – 150 15 мин 1 р/д е/д` | `EQUIPMENT` st-150, 15 мин |
| `Алмаг на заднюю поверхность … Алмаг 20 мин, 1 р/д е/д` | `CARD_ONLY` Алмаг, 20 мин |
| `Степпер 15 минут 1 р/д, ежедневно` | `CARD_ONLY` Степпер, 15 мин |
| `ЛФК в воде (нижняя конечность) 30 мин` | `POOL` «нижняя конечность» |
| `Бассейн 30 мин 1 р/д` | `POOL` «Бассейн» (группа не указана) |
| `Групповые занятия ЛФК` / `- спина` / `- ШОП` / `30 мин 2 р/д` | 2 назначения `DS_GROUP`: «ДС: спина», «ДС: ШОП», per_day 1 |
| `Массаж плечевого сустава` | `CARD_ONLY` Массаж (не группа ДС) |
| `Неизвестная процедура 10 мин` | `procedure = null`, подсвечена |
| Диагностика: `Консультация терапевта, медицинского психолога, медицинского логопеда, эрготерапевта, физического терапевта` | 3 назначения `CARD_ONLY`: Психолог, Логопед, Эрготерапевт |

### 6.3. Результат импорта
- **FR-IMP-10.** Импорт сразу создаёт программу и открывает её страницу. Отдельного экрана подтверждения нет: всё, что требует внимания, перечислено в блоке «Проверьте после импорта» (разные ИБ в шапках, нераспознанные строки, пол не определён, бассейн без группы) и подсвечено в назначениях. Исправления делаются на странице программы.
- **FR-IMP-11. Повтор.** Если в отделении уже есть программа того же пациента (совпал ИБ; если у одной из программ ИБ нет — совпало ФИО без учёта регистра, «ё» и лишних пробелов) и курсы пересекаются — программа не создаётся: показывается ссылка на существующую и кнопка «Всё равно создать новую». Обновление существующей программы из новой версии листа — фаза 4; до тех пор изменения вносятся на странице программы.
- **FR-IMP-13. Прошлые курсы.** Если пересекающегося курса нет, но у пациента есть завершённые программы в отделении (FR-PRG-10), перед созданием — экран сравнения: прошлый курс (даты, ШРМ, диагноз) и назначения рядом — совпало / добавлено в новом листе / было только в прошлом курсе; кнопки «Создать по новому листу», «Взять прошлый план», «Это другой пациент» (то же, что по новому листу, без связи с прошлым курсом).
- **FR-IMP-12.** Исходный файл не хранится. Не `.docx`, больше 5 МБ, повреждённый файл или нет таблицы с колонкой «Физиотерапия» — понятное сообщение без ошибки 500.

## 7. Расписание v2 (scheduling)

Переработано по итогам проверки первого прототипа врачом и специалистом ФР (05.10.2026). Из прототипа остаются смены, постоянная занятость (FR-STF-5), вид сетки шахматки и расчёт дней по ШРМ.

### 7.1. Что и как расписывается
- **FR-SCH-1. Дни занятий.** В день поступления и в день выписки у пациента нет никаких занятий: ни групп, ни бассейна, ни тренажёров, ни индивидуальных. Занятия — с `start_date + 1` по `end_date − 1`.
- **FR-SCH-2. Группы ЛФК, бассейн, тренажёры** — как в прототипе: ставятся автоматически на все дни занятий, пересобираются после импорта и любых изменений назначений, курса и расписания групп. Закреплённые вручную занятия не трогаются.
- **FR-SCH-3. Индивидуальные** — только в шахматке на дату (`BoardDay`), только по будням (пн–пт). На субботу и воскресенье шахматка не составляется; занятия в выходные инструкторы 2/2 ведут сами. На весь курс индивидуальные больше не подбираются.
- **FR-SCH-4. Целостность.** Пациент не может быть в двух местах в одно время (ограничение БД, как сейчас) — это правило и для автоматической, и для ручной постановки. В одной ячейке инструктора может стоять сколько угодно пациентов (FR-SCH-10); уникальность «инструктор + дата + слот» снимается.

### 7.2. Шахматка на день вперёд
- **FR-SCH-5. Создаётся сама.** Шахматка на следующий будний день есть всегда: она создаётся автоматически при первом обращении к расписанию в новый день (шахматка, страница программы, импорт). Отдельной кнопки и задания по расписанию на сервере нет. В пятницу создаётся понедельник. Расписание дальше следующего будного дня не составляется.
- **FR-SCH-6. Как создаётся** шахматка на дату D из предыдущей составленной шахматки P (обычно вчерашней, в понедельник — пятничной):
  1. постоянная занятость (FR-STF-5) — по распорядку на дату D;
  2. пациенты, у которых D не день занятий (выписка в D или курс закончился), не переносятся — их ячейки освобождаются;
  3. остальные пациенты из сетки P переносятся в ту же колонку и то же время, вместе с пометкой; у пары 2/2 колонка общая — работает напарник, пациент остаётся;
  4. если перенести нельзя (инструктор в D не работает, слот закрыт занятостью, пациент в это время занят группой, бассейном или закреплённым вручную тренажёром, индивидуальное отменено назначением) — пациент уходит в блок **«Не распределены»** на D. Тренажёр, поставленный подбором, индивидуальному не мешает: он сдвигается на ближайшее свободное время своего окна (вместимость, другие занятия пациента); если такого времени нет — «Не распределены». Чужие тренажёры для этого не двигаются — это решает специалист (решение 66). То же правило — при автоматической постановке (FR-SCH-7) и при постановке или переносе вручную (FR-SCH-10);
  5. блок «Отменены» переносится как есть (FR-SCH-11);
  6. новые пациенты (FR-SCH-7) раскладываются автоматически.
- **FR-SCH-7. Автоматическая постановка.** Новый пациент — тот, у кого на D назначено индивидуальное, но его нет ни в сетке, ни в блоках. Обычно это пациент, поступивший накануне: врач загрузил лист назначений, и пациент сразу ставится в уже созданную шахматку на завтра — после этого карту можно печатать со временем индивидуального. Сюда же — если врач увеличил `per_day`. Правила:
  - кандидаты — свободные дневные слоты работающих инструкторов: без постоянной занятости, без пациентов, пациент в это время свободен;
  - **равномерность:** выбирается колонка с наименьшим числом пациентов в этот день, затем раннее время, затем порядок колонок в шахматке — чтобы при свободных окнах у нескольких инструкторов индивидуальные не уходили одному;
  - два индивидуальных пациента в день не идут подряд (соседние слоты с перерывом не больше 10 минут; до и после обеда — не соседние);
  - лимит — `per_day` назначения, не больше `max_individual_per_day` отделения;
  - автоматически в одну ячейку ставится не больше одного пациента;
  - не нашлось места — пациент в «Не распределены».
- **FR-SCH-8. Мото-Л и Артромот.** Это одно из индивидуальных занятий пациента (не сверх лимита), которое проводится только с 18:00 — в вечерних слотах сетки (18:00, 18:40, 19:20). Вечерние слоты есть только у инструкторов 2/2 в их рабочий день. В листе назначений Мото-Л / Артромот — отдельной строкой; в справочнике это процедуры с признаком «вечернее индивидуальное», без своего расписания и **без строки в карте** (`in_card = false`). Если у пациента есть такое назначение, одно его индивидуальное автоматически ставится в вечерний слот, в ячейке пометка «Мото-Л» / «Артромот»; второе (если `per_day = 2`) — по общему правилу. Нет вечернего окна — «Не распределены». Мото-Л без назначенного индивидуального — предупреждение импорта.
- **FR-SCH-9. Сегодняшняя шахматка.** Автоматически ставится только в завтрашнюю. Пациента, поступившего или получившего индивидуальное сегодня, в сегодняшнюю шахматку специалист ставит вручную.

### 7.3. Ручная правка в шахматке
- **FR-SCH-10. Правка ячеек** (специалист ФР и администратор; врач смотрит). Править можно сегодняшнюю и завтрашнюю шахматку, прошедшие дни — только смотреть.
  - клик по свободному времени → список пациентов на лечении (сначала «Не распределены», затем «Отменены», затем остальные) с поиском по палате и фамилии → поставить;
  - перенести пациента в другую ячейку, убрать из сетки;
  - в одну ячейку можно поставить **сколько угодно** пациентов — время не делится (пациенты, которые выдерживают только 15 минут). Автоматически так не ставится никогда;
  - пометка в ячейке (Мото-Л, art, (шар) и т. п.);
  - вечерние слоты доступны вручную для любого пациента;
  - нарушения (пациент занят в это время, слот закрыт занятостью, инструктор не работает, два индивидуальных подряд) не дают сохранить — с понятным сообщением.
- **FR-SCH-10a. Перетаскивание** (согласовано 06.10.2026). Основной способ правки в шахматке — мышью, панель ячейки остаётся для поиска пациента и для клавиатуры:
  - пациента из ячейки перетаскивают в другую ячейку (в том числе в ячейку, где уже есть пациенты) — это перенос с теми же проверками, что в FR-SCH-10;
  - пациента из блоков «Не распределены» и «Отменены» перетаскивают в ячейку — это постановка;
  - в тренажёрах пациента перетаскивают на другое время **того же** тренажёра (тренажёр задан назначением); в одно время — несколько пациентов в пределах вместимости. Сверх вместимости или вне окна тренажёра — только с причиной, она видна пометкой в ячейке. Перенос касается только этой даты, «эту и все следующие» — на странице программы;
  - перетаскивать можно только своих пациентов (своего отделения) и только в шахматке, которую можно править; итог или ошибка — в панели, шахматка обновляется сразу.
  - пока пациента тащат или он выбран в панели (у ячейки с несколькими пациентами — при наведении на нужного), время, где у него другие занятия в этот день (группы, бассейн, тренажёры, индивидуальные), закрашивается красным — строки сетки и ячейки тренажёров; в подсказке и в списке «Перенести в…» — чем он занят. Само переносимое занятие не подсвечивается.
- **FR-SCH-11. Два блока под сеткой.**
  - **«Не распределены»** — пациенты с назначенным индивидуальным, которым не нашлось места: переполнение, инструктор не вышел, перенос невозможен (FR-SCH-6, 7, 8). Попадают сюда автоматически.
  - **«Отменены»** — пациенты, которых специалист убрал из сетки (обычно врач сказал устно). Остаются в блоке на следующие дни, пока пациент лечится, и не ставятся автоматически.
  - Из любого блока пациент ставится в сетку тем же действием, что и из списка. Пациент с отменённым в назначении индивидуальным (врач отменил в системе) в блоки не попадает.
- **FR-SCH-12. Правка сегодня переходит на завтра.** Любая правка сегодняшней шахматки (поставить, перенести, убрать, пометка) сразу применяется и к уже созданной завтрашней — если этого пациента в завтрашней не правили отдельно. Правка завтрашней на сегодняшнюю не влияет.
- **FR-SCH-13. Первая шахматка.** Если составленной шахматки ещё нет (первый запуск), все пациенты на лечении раскладываются автоматически, как новые (FR-SCH-7).

### 7.4. Шахматка и программа на экране
- **FR-SCH-14. Экран «Шахматка на дату»** — как в прототипе: слева колонки инструкторов в смене (пара 2/2 — одна колонка «A/ B»), строки — слоты сетки, включая вечерние; справа — тренажёры. Ячейка: «Nп Фамилия» (чужое отделение — «Nп ОМР X Фамилия»), пометка в конце, несколько пациентов — списком. Постоянная занятость — серым текстом. Под сеткой — блоки «Не распределены» и «Отменены» с числом пациентов. Навигация: назад — по прошлым будним дням (стрелка и календарь), вперёд — не дальше завтрашней шахматки (06.10, владелец: будущих шахматок нет, листать туда только путает); кнопки «Сегодня» и «Завтра» (в пятницу — «Понедельник»). То же на публичной шахматке.
- **FR-SCH-15. Публичная шахматка** `/board/` — то же только для чтения, без входа (сети — `PUBLIC_BOARD_NETWORKS`), без блоков и ссылок.
- **FR-SCH-16. Страница программы:** типичный день и календарь групп, бассейна и тренажёров — как в прототипе; индивидуальные — из шахматок (сегодня, завтра и прошедшие), и в каком блоке пациент, если он не в сетке. Правки индивидуальных на странице программы нет — только в шахматке.
  - Над расписанием — строка на каждую составленную шахматку (сегодня, завтра): время и инструктор или блок, где пациент («Не распределены» — красным), со ссылкой на шахматку.
  - Типичный день и карта берут индивидуальное только из ближайшей шахматки, где пациент стоит (сегодня, иначе завтра); прошедшие дни на него не влияют и отклонений не дают.
  - В календаре курса у индивидуального: время со ссылкой на шахматку дня, «не распределён» / «отменён», «…» — шахматка на этот будний день ещё не составлялась; выходные — серым.
- **FR-SCH-17.** Отчёт «Загрузка инструкторов» за период (по шахматкам) и выгрузка шахматки на дату в `.xlsx` — остаются из прототипа.

### 7.5. Что убирается из прототипа
Подбор индивидуальных на весь курс; автоматическая перестройка при болезни инструктора со сводкой и «Вернуть как было» (`StaffChange`) — вместо неё «Не распределены»; инструктор по желанию пациента (`preferred_instructor`) — его заменяет перенос «в ту же ячейку» (удалён 06.10 вместе с полем, кнопкой в ячейке и блоком на странице программы, решение 65); ручная правка индивидуальных на странице программы; индивидуальные в выходные без инструктора; кнопка «Подобрать заново» — расписание групп и тренажёров пересобирается само. Удалено 06.10 (шаг 3б.4): индивидуальная часть движка подбора, `StaffChange` и экраны «Перестройки», правка индивидуальных на странице программы.

### 7.6. Права
Шахматка, распорядок, смены, блоки — специалист ФР любого отделения и администратор; пациента другого отделения ставит и убирает только специалист ФР этого отделения. Врач — просмотр.

### 8.2. Заполнение
- **FR-CRD-2.**
  - **Шапка:** ФИО полностью; `({sex}) {age} {год|года|лет}` с правильным склонением; врач; название отделения.
  - **Типичный день:** строки блока — дневные слоты сетки инструкторов по порядку (вечерние не печатаются). Занятие попадает в строку слота, с которым больше всего пересекается по времени; не пересекается ни с одним (вечер, обед) — отдельная строка со своим временем, чтобы не занять чужое окно. В строке — фактическое время начала (значение Excel `time`, формат `Ч:ММ`), `card_label` процедуры, `place`. Несколько занятий в одном слоте — одна строка через «/» («Pablo/st-150»); у занятия, которое начинается позже времени строки, время пишется в подписи («st-150/Имитрон 13:15»). Слот без занятий — **окно**: время слота есть, процедура и место пустые — по окнам инструкторы видят, когда пациент свободен. Индивидуальное занятие — время и инструктор из ближайшей шахматки (сегодня или завтра), где стоит пациент; пациента нет в сетке — строки для него нет (окно). Место — пусто или `place` из справочника. Дневных слотов больше, чем строк шаблона (10) → выгрузка не выполняется, сообщение со списком.
  - **Даты:** настоящие даты Excel, формат `ДД.ММ`.
  - **Нижний блок:** назначения с `in_card = true` (все виды, включая `CARD_ONLY`), по `Prescription.card_order` (порядок назначений), текст — `card_label`. Строк больше, чем вмещает шаблон → сообщение с количеством, выгрузка не выполняется.
  - Клетки под датами остаются пустыми (отметки от руки). Даты вне `start_date…cancel_date` назначения, а также день поступления и день выписки (FR-SCH-1) и дни после выбытия (FR-PRG-9) заштриховываются (серая заливка).
- **FR-CRD-3.** Если расписание по дням отличается от типичного (`DAY_DEVIATION`), перед выгрузкой — предупреждение со списком дат. Выгрузить можно.
- **FR-CRD-4.** Сохраняются оформление шаблона: шрифты, рамки, объединения, логотипы, область печати, ориентация, масштаб. Имя файла: `Программа_{Фамилия}_{ИБ}_{дата поступления}.xlsx`.
- **FR-CRD-5.** Журнал выгрузок: пользователь, время, программа.
- **FR-CRD-6.** (Фаза 4) Кнопка «PDF» — конвертация того же xlsx через LibreOffice в режиме без интерфейса. Если LibreOffice недоступен, кнопка скрыта.
- **Критерии приёмки:**
  - автотест открывает выгрузку через openpyxl и проверяет значения и типы в ячейках по mapping для ШРМ 3/4/5;
  - логотипы присутствуют в файле;
  - **ручная проверка владельцем в MS Excel:** файл открывается без предупреждений и печатается на 1 странице (ШРМ5 — как в шаблоне).

## 12. Тестирование

- **Unit (домен):** парсер листа назначений и сопоставление (§6), расчёт дат курса, склонение «год/года/лет», заполнение карты, `is_working`, перенос шахматки и автоматическая постановка (равномерность, вечерние слоты, «подряд»).
- **Интеграционные (сервисы + PostgreSQL):** права доступа, импорт, правка программы и назначений, удаление; шахматка — автосоздание, блоки, правка ячеек, правка сегодня → завтра, «пациент не в двух местах».
- **Экспорт:** чтение выгруженной карты и сверка значений, типов и наличия изображений.
- **Ручная приёмка владельцем:** печать из MS Excel; сценарий «лист назначений → программа → правка → печать».
- Тестовые данные — обезличенные фикстуры pytest и листы назначений из `tests/sheets.py`; реальные ФИО из `primary_docs/` в репозиторий тестов не попадают.
