## 1. Цель и границы

### 1.1. Цель
Убрать ручное копирование при составлении «Индивидуальной программы медицинской реабилитации». Система — это **список индивидуальных программ**. Каждая программа:
1. создаётся из листа назначений врача: врач загружает свой `.docx` (тот же шаблон, что он ведёт для письменной документации), назначения появляются в вебе, при необходимости врач правит их там же — без повторной загрузки файла. Ручной ввод — запасной путь;
2. сама получает расписание: групповые занятия ЛФК и бассейн — по расписанию групп, тренажёры — по окну тренажёров, индивидуальные занятия — в «окна» пациента и инструкторов с равномерной нагрузкой на инструкторов;
3. правится вручную в вебе — любое занятие, время, инструктор;
4. выгружается в `.xlsx` по шаблону карты для печати из MS Excel.

Расписания, из которых строятся программы, тоже ведутся в вебе, а не в Excel: расписание групп ЛФК и бассейна, окна тренажёров, графики смен инструкторов и общая шахматка инструкторов. Система — не МИС: выписки, истории болезни и медицинских данных сверх нужного для программы в ней нет. Отделений — сколько угодно.

### 1.2. Входит
Всё, что описано в §4–§9.

### 1.3. Не входит
- Интеграция и API с МИС, обмен с внешними системами.
- Электронные отметки о проведении занятий (отметки ставятся от руки на распечатке).
- Обратная загрузка правок из Excel (Excel только для печати).
- Методики индивидуальных занятий (PNF, RC, HUR) — их пишет инструктор от руки.
- Расписание по времени для Tigo, Алмага, Степпера, массажа, Орторент-дорожки, консультаций эрготерапевта, психолога и логопеда — для них только строка в карте.
- Учёт инструкторов бассейна.
- Лекарственные и диагностические назначения из листа назначений.
- Мобильное приложение. Достаточно веб-интерфейса для десктопа (ширина от 1280 px).

## 2. Термины

См. глоссарий в `CLAUDE.md`. Дополнительно:
- **Индивидуальная программа (Program)** — программа реабилитации пациента на один курс: данные из листа назначений, назначения и расписание. Повторное поступление того же человека — новая программа.
- **Курс** — даты программы: `start_date … start_date + course_days[ШРМ] − 1`, календарные дни.
- **Типичный день** — расписание, которое печатается в верхнем блоке карты «Расписание занятий» (время | процедура | место).
- **Бронирование (Booking)** — занятие пациента в конкретную дату и время.
- **Блок (InstructorBlock)** — слот инструктора, занятый не пациентом: «Метод. работа», ведение группы, БОС, прочее. Блок на одну дату или постоянный распорядок инструктора (FR-STF-5). В слоте с блоком индивидуальных занятий нет — ни в подборе, ни вручную.
- **Закреплённое бронирование (pinned)** — поставленное или изменённое вручную. Движок его не трогает.

## 3. Пользователи и роли

| Роль | Код | Кратко |
|---|---|---|
| Администратор | `admin` | Всё, включая отделения, пользователей, справочники; удаление программ и пользователей |
| Врач | `doctor` | Индивидуальные программы своих отделений: импорт листа назначений, правка данных и назначений, выгрузка карты. Расписание и шахматка — только просмотр |
| Специалист по физической реабилитации | `rehab` | Формирует и правит расписание программ; расписание групп и тренажёров, шахматка, блоки, смены, справочники, выгрузки. Данные и назначения — просмотр |

Других ролей нет (ответ 21). **Все сотрудники отделения видят все программы этого отделения** (решение владельца 04.10), независимо от того, кто их создал. Инструкторы и остальные сотрудники смотрят шахматку без входа (FR-ACC-5).

Полная матрица прав — в `03-architecture.md` §8. Требования:
- **FR-ACC-1.** Вход по логину и паролю, выход, смена пароля пользователем, сброс пароля администратором. Сессия завершается после 8 часов бездействия (параметр).
- **FR-ACC-2.** Пользователь состоит в одном или нескольких отделениях, в каждом — со своей ролью (`Membership`). Пациентов отделения, в котором он не состоит, пользователь не видит (ни в списках, ни по прямой ссылке → 404).
- **FR-ACC-3.** У пользователя есть поле `short_name` («Петлина К.И.») — оно печатается в карте как врач.
- **FR-ACC-4.** Права проверяются на уровне сервисов (сервис получает пользователя и проверяет роль и отделение), а не только в шаблонах.
- **FR-ACC-5.** Публичная шахматка (ответ 18): страница `/board/` — шахматка на дату только для чтения, без входа в систему. Показывает то же, что бумажная шахматка: «Nп Фамилия», блоки, тренажёры. Без ФИО полностью, диагнозов, ссылок на карточки и выгрузок. Кто может открыть страницу, задаёт настройка `PUBLIC_BOARD_NETWORKS` — список сетей через запятую:
  - **локальная разработка:** не задана — доступ свободный;
  - **прод (фаза 5):** обязательно указываются сети клиники, запросы с других адресов получают 404. Пункт входит в чек-лист `docs/deploy.md`.
- **Критерий приёмки:** тесты на каждую ячейку матрицы прав для ключевых операций (создать программу, применить подбор, править шахматку, выгрузить карту).

## 4. Справочники (catalog, staff, org)

Справочники редактируются в админке Django (у роли `rehab` — доступ к своему подмножеству, решение 13); расписание групп и окна тренажёров — ещё и на экране «Расписание групп» (FR-SCH-18). Удаление используемых записей запрещено, вместо него — флаг `is_active`.

### 4.1. Отделения
- **FR-ORG-1.** `Department`: название («ОМР № 4»), код, `course_days` (по умолчанию `{3: 11, 4: 15, 5: 20}`), `max_individual_per_day` (по умолчанию 2), `is_active`.
- **FR-ORG-2.** Новое отделение добавляется без изменения кода.

### 4.2. Процедуры
- **FR-CAT-1.** `Procedure`: `name`, `card_label`, `synonyms` (список строк), `kind` ∈ {`LFK_GROUP`, `POOL`, `INDIVIDUAL`, `EQUIPMENT`, `CARD_ONLY`}, `default_duration_min`, `place`, `equipment` (для `EQUIPMENT`), `department` (null = для всего центра), `is_active`. Порядок строк в карте задаёт назначение, а не процедура (FR-PRG-3).
- **FR-CAT-2.** Для бассейна: процедура «Бассейн» (`POOL`, признак `group_choice` — «тип не указан», своего расписания у неё быть не может) и процедуры групп бассейна «ЛФК в воде: верхняя конечность / нижняя конечность / спина» (`POOL`, с сессиями).

### 4.3. Расписание групп
- **FR-CAT-3.** `GroupSession`: `procedure`, `start_time`, `duration_min`, `place`. Расписание одинаково каждый день недели. У процедуры может быть несколько сессий в день. Ограничения по вместимости нет.
- Длительность по умолчанию: ЛФК — 30 мин, бассейн — 30 мин (подтверждено, ответ 5; остаётся параметром).

### 4.4. Тренажёры
- **FR-CAT-4.** `Equipment`: `name`, `window_start` (13:00), `window_end` (15:00), `step_min` (15), `capacity` (по умолчанию 1, настраивается), `duration_min` (15), `is_active`. Возможные начала: `window_start + k·step_min`, при этом `start + duration ≤ window_end`.
- **FR-CAT-4a.** На тренажёре работает один инструктор (ответ 12). Движок ставит не больше `capacity` пациентов на одно время. Вручную специалист может записать на одно время больше пациентов (ответ 13): система предупреждает `EQUIPMENT_FULL`, сохранение требует пометки (`note`), пометка видна в шахматке.

### 4.5. Сетка слотов инструкторов
- **FR-CAT-5.** Сетка слотов (одна на центр): записи `InstructorSlot` `(start, end)` по порядку времени. По умолчанию: 09:10–09:40, 09:50–10:20, 10:30–11:00, 11:10–11:40, 13:00–13:30, 13:40–14:10, 14:20–14:50, 15:00–15:30, 15:40–16:10, 16:20–16:50, 18:00–18:30, 18:40–19:10, 19:20–19:50. Вечерние слоты имеют флаг `evening` и по умолчанию **не используются движком** (только ручная постановка).
- Слот — запись `InstructorSlot` (начало, конец, «вечерний»); бронирования и блоки ссылаются на неё внешним ключом (`slot`), а не на позицию в списке. Слот с бронированиями нельзя удалить (`PROTECT`), а менять его время запрещает сервис со списком конфликтов. Соседство слотов (`INDIVIDUAL_ADJACENT`) считается по времени, а не по номеру. Везде ниже `slot_index` читается как `slot`.

### 4.6. Инструкторы и смены
- **FR-STF-1.** `Instructor`: `full_name`, `short_name`, `partner` (симметричная связь: если у A напарник B, то у B напарник A — поддерживается сервисом), `display_order`, `is_active`.
- **FR-STF-2.** `ShiftPattern`: `instructor`, `pattern` ∈ {`2/2`, `5/2`, `daily`}, `anchor_date`, `valid_from`, `valid_to`. Для `2/2`: рабочий день, если `(date − anchor_date).days mod 4 ∈ {0, 1}`. Для `5/2`: понедельник–пятница.
- **FR-STF-3.** `ShiftException`: `instructor`, `date`, `is_working`, `reason`. Исключение важнее шаблона.
- **FR-STF-4.** Экран «Смены»: календарь месяца, строки — инструкторы, ячейки — рабочий или нерабочий день (как `Лист3` в `instructions_schedule.xlsx`). Клик по ячейке создаёт или удаляет исключение.
- **FR-STF-5. Постоянный распорядок инструктора** (решение 45). Специалист ФР задаёт, что инструктор делает в слоте каждый свой рабочий день: ведёт группу (из расписания групп), БОС, «Метод. работа», прочее — с периодом действия `valid_from…valid_to`. Пример из шахматки: Овсиенко — «Эрго общая» 9:10, «i-can нога» 10:30, БОС 13:00–14:50; Атаманчук — «Метод. работа» 15:00–16:50. На конкретную дату распорядок можно снять или заменить разовым блоком. Шахматка и подбор видят распорядок как блоки.
- **FR-STF-6.** Отметка «не работает» на дату (болезнь, не вышел — `ShiftException`) ставится в шахматке или на экране «Смены» одним действием и сразу запускает перестройку его занятий (FR-SCH-13).
- **Критерий приёмки:** unit-тесты `is_working()` для 2/2, 5/2, daily, исключений и границ `valid_from`/`valid_to`.

### 4.7. Начальное наполнение
- **FR-CAT-6.** Management-команда `load_initial_catalog` загружает:
  - группы ЛФК и их сессии из `lfk.xlsx`;
  - группы бассейна из `basseyn.xlsx`;
  - тренажёры st-150, Имитрон, Pablo;
  - процедуры `CARD_ONLY` (T.tigo, Алмаг, Степпер, Массаж, Орторент-дорожка, Эрготерапевт, Психолог, Логопед, механотерапия);
  - процедуру «Индивидуальное занятие» (`INDIVIDUAL`, 30 мин);
  - сетку слотов;
  - отделение «ОМР № 4».

  Синонимы задаются в фикстуре (см. §6.2). Команда идемпотентна.
- Время в `lfk.xlsx` и `basseyn.xlsx` хранится как доля суток (`0.381944…` = 09:10) — конвертировать с округлением до минуты.

## 5. Индивидуальные программы (programs)

- **FR-PRG-1.** `Program`: `department`, `full_name`, `sex` (М/Ж, может быть пустым), `age` (целое, необязательное), `history_number` (ИБ, необязательный), `room` (строка: «9», «5а»), `shrm` ∈ {3, 4, 5}, `diagnosis` (необязательный), `attending_doctor` (FK User), `start_date`, `end_date`, `end_date_manual`, `source` ∈ {`import`, `manual`}, `import_warnings` (список строк), `preferred_instructor` (инструктор по желанию пациента, необязательно; задаёт специалист ФР — решение 44), `created_at`, `updated_at`. История изменений — NFR-5.
- **FR-PRG-2.** `end_date` по умолчанию: `start_date + course_days[shrm] − 1`. Врач может изменить её — это продление или досрочное окончание программы (`end_date_manual = true`), дальше она не пересчитывается. Если дату не меняли вручную, она пересчитывается при смене ШРМ или даты начала. Даты назначений должны помещаться в курс — иначе сохранение отклоняется со списком назначений, которые нужно поправить.
- **FR-PRG-3.** `Prescription`: `program`, `procedure` (пусто — строка не распознана), `raw_text` (строка из листа назначений), `duration_min`, `per_day`, `start_date` / `cancel_date` (пусто — с начала / до конца курса; `cancel_date` — первый день без процедуры, не позже `end_date`), `in_card`, `card_order` (порядок строк в карте = порядок назначений, врач может переставить).
  - Для `INDIVIDUAL`: `per_day` не больше `max_individual_per_day` отделения; импорт урезает больше лимита до лимита с предупреждением.
  - Для `LFK_GROUP` и `POOL`: `per_day` — сколько раз в день пациент ходит в **эту** группу. Импорт всегда ставит 1 (FR-IMP-3); больше врач ставит вручную, если группа идёт несколько раз в день (Нейро-тренинг в 10:30 и 14:20).
  - Для `POOL` с процедурой «Бассейн» (группа не указана) группу бассейна выбирает специалист ФР в блоке «Расписание» программы: список групп с временем их занятий. Выбор хранится в `pool_group` назначения, запись врача «Бассейн» не меняется; после выбора расписание пересобирается сразу. Выбор можно сменить или снять.
- **FR-PRG-4.** Экран **«Индивидуальные программы»** (главный): ФИО, палата, ШРМ, даты курса, врач, состояние программы — «требует проверки» (есть предупреждения импорта или нераспознанные назначения), затем «расписание не составлено / составлено / есть конфликты» (с фазы 2). Фильтр: текущие (курс не закончился) / завершённые / все. Поиск по ФИО и ИБ без учёта регистра и «ё». Порядок — по номеру палаты.
- **FR-PRG-5.** Создание: главная кнопка — **«Загрузить лист назначений»** (§6); запасная — «Создать вручную» (форма тех же полей). На экране загрузки отделение видно и выбирается явно (по умолчанию — из шапки; предлагаются отделения, где пользователь врач); после загрузки шапка переключается на это отделение.
- **FR-PRG-8.** Удаление программы — только администратор, со страницей подтверждения; вместе с программой удаляются назначения, расписание и журнал выгрузок, запись об удалении остаётся в истории. Удаление пользователей — администратор в админке; лечащего врача программ удалить нельзя, пока программы не переданы другому врачу (или пользователь просто отключается).
- **FR-PRG-6.** Страница программы — это и есть программа: шапка (данные пациента, курс, врач), блок «Проверьте после импорта» (предупреждения; врач закрывает его кнопкой), **назначения** (правка, удаление, порядок, смена процедуры у нераспознанной строки), **расписание** (типичный день и календарь курса, §7.4), кнопка **«Скачать карту»** (§8).
- **FR-PRG-7.** Выписки и статусов нет. Программа завершена, когда её курс закончился. Досрочное окончание или продление — правка даты окончания. Завершённые программы остаются в списке (фильтр) и доступны для выгрузки.
- **Права** (§3): создавать, импортировать и править данные и назначения — врач отделения и администратор; специалист ФР — просмотр данных и назначений, правка расписания (§7).

## 6. Импорт листа назначений (.docx)

Главный способ создать программу. Образец — `primary_docs/pacient.docx` (шаблон, который врачи ведут для письменной документации).

### 6.1. Разбор документа
- **FR-IMP-1. Шапка** — первый абзац, содержащий `ФИО`. Поля:
  - `ФИО\s+(?P<fio>.+?)\s{2,}ИБ` (обязательно);
  - `ИБ\s*№\s*(?P<ib>\d+)`, `Диагноз:\s*(?P<dx>\S+)` (необязательно);
  - `ШРМ\s*(?P<shrm>[345])`, `Палата\s*№\s*(?P<room>\S+)` (обязательно).

  Если шапка встречается несколько раз и значения отличаются (в образце ИБ `5402` и `513402`) — берётся первое значение и записывается предупреждение со всеми вариантами.
- **FR-IMP-2. Физиотерапия** — первая таблица, в строке заголовка которой есть ячейка `Физиотерапия`. Из каждой следующей строки берутся: текст ячейки «Физиотерапия», дата в ячейке слева (`дд.мм.гг`) — дата назначения, дата в ячейке справа — дата отмены. Абзацы ячейки объединяются через перевод строки, пустые строки пропускаются.
- **FR-IMP-3. Группы.** Абзацы, начинающиеся с `-` (`–`, `—`), — перечисление групп внутри строки «Групповые занятия ЛФК». Каждая группа становится отдельным назначением с общей длительностью и частотой 1 р/д: «2 р/д» под списком — это сколько групповых занятий в день на весь список, т. е. каждая группа идёт один раз (решение 42). Если число в «р/д» не совпадает с числом групп в списке — предупреждение импорта; частоту группы врач может поправить в назначении.
- **FR-IMP-4.** Длительность: `(\d+)\s*мин` (включая «минут»). Частота: `(\d+)\s*р/д`.
- **FR-IMP-5. Консультации.** В колонке «Диагностические назначения» той же таблицы строка, начинающаяся с «Консультац», перечисляет специалистов через запятую («Консультация терапевта, медицинского психолога, медицинского логопеда, эрготерапевта…»). Каждый специалист сопоставляется со справочником по синонимам; совпавшие (психолог, логопед, эрготерапевт) становятся назначениями `CARD_ONLY`, остальные (терапевт и т. п.) пропускаются без предупреждения. Остальное содержимое колонки и таблицы лекарств не разбирается.
- **FR-IMP-6. Даты курса.** Дата начала программы — самая ранняя дата назначения в таблице. Назначение, начатое позже, получает `start_date`; отменённое — `cancel_date`. Дата окончания — по ШРМ (FR-PRG-2).
- **FR-IMP-7. Пол, возраст, врач.** В листе их нет:
  - пол определяется по отчеству (`…вич`/`…ич` → М, `…вна`/`…чна` → Ж); не определился — поле пустое и предупреждение;
  - возраст — необязательное поле, врач может дописать на странице программы; в карте без возраста печатается только пол;
  - лечащий врач — пользователь, загрузивший файл (если он врач отделения), иначе его выбирают на экране загрузки.

### 6.2. Сопоставление со справочником
- **FR-IMP-8.** Нормализация строки и синонимов: нижний регистр, `ё→е`, все виды тире и дефисов, пробелы и точки удаляются. Совпадение — синоним входит в нормализованную строку. Если подошло несколько процедур, побеждает самый длинный синоним. Нет совпадений → `procedure = null`, строка подсвечивается на странице программы.
- **FR-IMP-9.** Бассейн: строка содержит `бассейн` или `в воде`. Группа определяется по `верхн` / `нижн` / `спин`. Не найдена — процедура «Бассейн» (группу выберет специалист ФР).
- **Эталонные примеры** (обязательные тест-кейсы):

| Строка | Ожидаемый результат |
|---|---|
| `Групповые занятия ЛФК` / `- Эрго общая` / `- I can нога` / `30 мин 2 р/д е/д` | 2 назначения: `LFK_GROUP` «Эрго общая» и «I can нога», 30 мин, per_day 1 (две группы в день — каждая один раз), без предупреждений |
| `Групповые занятия ЛФК` / `- Эрго общая` / `30 мин 2 р/д` | `LFK_GROUP` «Эрго общая», per_day 1 + предупреждение «2 р/д на 1 группу» |
| `Индивидуальное занятие ЛФК 30 мин 1 р/д е/д` | `INDIVIDUAL`, 30 мин, per_day 1 |
| `Thera Trainer Tigo 15 мин 2 р/д е/д` | `CARD_ONLY` T.tigo |
| `Имитрон  15 мин 1 р/д е/д` | `EQUIPMENT` Имитрон, 15 мин |
| `ST – 150 15 мин 1 р/д е/д` | `EQUIPMENT` st-150, 15 мин |
| `Алмаг на заднюю поверхность … Алмаг 20 мин, 1 р/д е/д` | `CARD_ONLY` Алмаг, 20 мин |
| `Степпер 15 минут 1 р/д, ежедневно` | `CARD_ONLY` Степпер, 15 мин |
| `ЛФК в воде (нижняя конечность) 30 мин` | `POOL` «нижняя конечность» |

| Диагностика: `Консультация терапевта, медицинского психолога, медицинского логопеда, эрготерапевта, физического терапевта` | 3 назначения `CARD_ONLY`: Психолог, Логопед, Эрготерапевт |

### 6.3. Результат импорта
- **FR-IMP-10.** Импорт сразу создаёт программу и открывает её страницу. Отдельного экрана подтверждения нет: всё, что требует внимания, перечислено в блоке «Проверьте после импорта» (разные ИБ в шапках, нераспознанные строки, пол не определён, бассейн без группы) и подсвечено в назначениях. Исправления делаются на странице программы.
- **FR-IMP-11. Повтор.** Если в отделении уже есть программа того же пациента (совпал ИБ; если у одной из программ ИБ нет — совпало ФИО без учёта регистра, «ё» и лишних пробелов) и курсы пересекаются — программа не создаётся: показывается ссылка на существующую и кнопка «Всё равно создать новую». Обновление существующей программы из новой версии листа — фаза 4; до тех пор изменения вносятся на странице программы.
- **FR-IMP-12.** Исходный файл не хранится. Не `.docx`, больше 5 МБ, повреждённый файл или нет таблицы с колонкой «Физиотерапия» — понятное сообщение без ошибки 500.

## 7. Расписание (scheduling)

### 7.1. Модель и целостность
- **FR-SCH-1.** `Booking` и `InstructorBlock` — как в `03-architecture.md` §4.5.
- **FR-SCH-2.** Ограничения на уровне БД:
  - частичный уникальный индекс `Booking(instructor, date, slot_index)` для `kind = INDIVIDUAL`;
  - уникальный `InstructorBlock(instructor, date, slot_index)`;
  - `ExclusionConstraint` на `Booking`: одна `program` и пересекающиеся `tsrange(date + start, date + end)` запрещены (расширение `btree_gist`).
- **FR-SCH-3.** Сервис записи бронирования инструктора проверяет, что нет блока в том же слоте, и блокирует строку `Instructor` (`select_for_update`). Запись на тренажёр блокирует строку `Equipment` и считает `count(bookings в интервале)`: сверх `capacity` — только ручная запись с пометкой (FR-CAT-4a).
- **FR-SCH-4.** У `Booking` есть поле `version`. Ручная правка передаёт версию, и если она не совпала — сообщение «запись изменена другим пользователем, обновите».

### 7.2. Проверка конфликтов (единый валидатор)
- **FR-SCH-5.** Доменная функция `validate(booking, context) -> list[Violation]` используется и движком, и ручной правкой, и импортом. Нарушения:
  - `PATIENT_OVERLAP` — пересечение интервалов пациента (сравниваются реальные интервалы: например, бассейн 09:45–10:15 пересекается со слотом 09:50–10:20);
  - `INSTRUCTOR_OFF_SHIFT` — инструктор не в смене;
  - `INSTRUCTOR_BUSY` — слот занят пациентом или блоком;
  - `EQUIPMENT_WINDOW` — время вне окна тренажёра или не на шаге;
  - `EQUIPMENT_FULL` — вместимость тренажёра исчерпана;
  - `INDIVIDUAL_LIMIT` — индивидуальных занятий больше назначенного или больше лимита отделения;
  - `INDIVIDUAL_ADJACENT` — два индивидуальных занятия пациента в один день идут подряд: в соседних слотах сетки, между которыми перерыв не больше 10 минут (ответ 9). Слоты до и после обеда (11:10–11:40 и 13:00–13:30) соседними не считаются;
  - `OUT_OF_COURSE` — дата вне курса или вне `start_date…cancel_date` назначения.
- Нарушения делятся на три вида:
  - **неустранимые** — `PATIENT_OVERLAP`, `INSTRUCTOR_BUSY`, `INDIVIDUAL_ADJACENT`: сохранить нельзя никому;
  - **с пометкой** — `EQUIPMENT_FULL`: роль `rehab` или `admin` сохраняет, если заполнена пометка (`note`);
  - **с подтверждением** — остальные: роль `rehab` или `admin` сохраняет после явного подтверждения с указанием причины.
- Движок не создаёт ни одного нарушения: для него все виды жёсткие.

### 7.3. Движок подбора (вариант A — жадный)
Интерфейс: `ScheduleEngine.propose(snapshot: Snapshot) -> Proposal`. Это чистый Python без Django, в пакете `apps/scheduling/domain/`.

**Snapshot:** программа (даты курса, назначения), сессии групп, сетка слотов, инструкторы с функцией смен, напарники, все бронирования и блоки за даты курса (всех отделений, кроме бронирований этой программы, которые не `pinned`), тренажёры, настройки отделения.

**Шаги:**
1. **Группы ЛФК.** Для каждого назначения `LFK_GROUP` выбрать `per_day` разных сессий — по очереди первую по времени, которая подходит в наибольшее число дней и не пересекается с уже выбранными занятиями пациента. Выбранное время одинаково на все даты назначения; в день, где оно занято, — другая сессия группы (`Warning(DAY_DEVIATION)`), нет свободной — день остаётся пустым, `Conflict(GROUP_OVERLAP)` со списком дат (решение 28). Сессий в расписании меньше, чем `per_day`, → ставится сколько есть + `Conflict(GROUP_FREQUENCY)` (решение 42).
2. **Бассейн.** Аналогично для `POOL` с конкретной группой. Тип не указан → `Conflict(POOL_TYPE_REQUIRED)`, шаг пропускается.
3. **Индивидуальные.** `need = min(per_day, max_individual_per_day)` единиц на каждую дату. Для каждой единицы:
   - инструктор подбирается только на будни (решение 56): кандидаты, покрытие и загрузка считаются по будним датам; в субботу и воскресенье единица ставится в свой слот без инструктора (пациент занят — ближайший свободный слот, `DAY_DEVIATION`);
   - кандидаты: «команда» × «слот» по всем не вечерним слотам, где команда — пара напарников или одиночный инструктор; слоты с блоками (метод. работа, группа, БОС, FR-STF-5) не кандидаты;
   - если у программы есть `preferred_instructor` (решение 44): в его рабочие дни — только он; в остальные дни или если у него нет свободного слота — его напарник по 2/2, затем любой свободный инструктор по общему правилу, с `Warning(PREFERRED_REPLACED)` на эти даты;
   - **покрытие** кандидата — доля дат курса, на которые «работающий сегодня член команды свободен в этом слоте, а пациент свободен в этот интервал»;
   - **загрузка** команды — число индивидуальных бронирований её членов за даты курса (с учётом уже выбранного в этом прогоне);
   - кандидаты, дающие `INDIVIDUAL_ADJACENT` с другой индивидуальной единицей пациента, отбрасываются;
   - **ключ сортировки** (решение 56): среди кандидатов с покрытием не меньше половины будних дат — `(средняя загрузка на рабочий будний день команды, −покрытие, slot_index, display_order)`; таких нет — `(−покрытие, …)`;
   - выбирается первый кандидат. На даты, где он не проходит, подбирается замена на день: любой свободный работающий инструктор в том же слоте (с минимальной загрузкой), иначе в ближайшем свободном слоте. Каждая замена → `Warning(DAY_DEVIATION)`. Не нашлось ничего → `Conflict(INDIVIDUAL_UNPLACED, date)`.
   - прошлые автоматические постановки этой программы (`previous`, решение 49) ставятся первыми, если в дату ещё допустимы, и засчитываются в покрытие своего кандидата — недостающие даты добираются тем же инструктором и слотом (решение 52);
   - порядок замены на день: работающий свободный член команды в том же слоте → любой свободный инструктор в том же слоте с наименьшей загрузкой → ближайший по времени слот (сначала команда, затем любой). По желанию пациента: он сам (основной слот, затем ближайший) → напарник → общее правило (решение 53). Лимит в день — на все индивидуальные назначения программы вместе с закреплёнными (`Warning(INDIVIDUAL_LIMIT)` с датами, решение 54).
4. **Тренажёры.** (Идут после индивидуальных: окно тренажёра гибче сетки слотов.) Для каждого `EQUIPMENT` с `per_day = n`: выбрать `n` разных начал в окне, где на все даты есть вместимость и пациент свободен. Ключ: `(−покрытие, загруженность времени, start)`. Отклонения по дням → `Warning(DAY_DEVIATION)`. Невозможно → `Conflict(EQUIPMENT_UNPLACED, date)`.
5. **Proposal** = список бронирований + конфликты + предупреждения + сводка загрузки инструкторов «до/после».

**Свойства:**
- **Закрепление — цель, а не правило** (ответ 7). Один инструктор (пара 2/2) и одно время на весь курс — то, к чему стремится движок. Если в какие-то дни это невозможно, он ставит замену на день, а не оставляет дыру. Перенос вручную («эта дата» / «эта и все следующие», FR-SCH-9) и замена при изменении смен (FR-SCH-13) — штатные операции.
- **Детерминированность:** одинаковый снимок → одинаковый результат.
- Бронирования с `pinned = true` не меняются и учитываются как занятость.
- Подбор одного пациента занимает до 2 секунд при 150 активных пациентах.

**Обязательные тест-сценарии** (`tests/scheduling/test_engine.py`):
1. Пациент ШРМ4 с группами «Эрго общая», «I can нога», 1 индивидуальным, st-150 → все поставлены, время одинаковое на 15 дат.
2. Две группы в одно время (I can нога и Нейро-тренинг в 10:30) → Нейро-тренинг уходит на 14:20.
3. Пара 2/2 «Паршуков/Ким» — пациент закреплён за парой, в каждую дату стоит работающий член пары, время одно.
4. Три одинаковых пациента подряд → индивидуальные распределяются по разным командам (равномерность).
5. Бассейн нижняя конечность 09:45 → индивидуальное не ставится в 09:50–10:20 (пересечение интервалов).
6. Все слоты всех инструкторов заняты в одну дату → `INDIVIDUAL_UNPLACED` только для этой даты.
7. Вместимость st-150 = 2 и два пациента уже в 13:00 → третий получает другое время.
8. `pinned`-бронирование не меняется при повторном подборе.
9. В снимке `per_day = 3` при лимите 2 (сервис такого не пропустит — FR-PRG-3; проверка защиты движка) → ставится 2 + предупреждение.
10. Пациент другого отделения занимает слот → этот слот недоступен.
11. Два индивидуальных в день, свободны только соседние слоты 09:10 и 09:50 у всех команд → второе занятие ставится не подряд (или `INDIVIDUAL_UNPLACED`), подряд — никогда.

### 7.4. Расписание на странице программы
- **FR-SCH-6.** Верхняя часть — «Типичный день»: таблица время | процедура | место | инструктор или тренажёр (как будет в карте). Строки — дневные слоты сетки инструкторов (правило — FR-CRD-2); строка без занятий — «окно», в это время пациент свободен и туда ставится индивидуальное занятие. Нижняя часть — календарь курса: строки — даты, колонки — занятия. Отклонения от типичного дня подсвечены.
- **FR-SCH-7.** (Отменено решением 50 — индивидуальные тоже ставятся сразу; текст оставлен для истории.) Кнопка «Подобрать» → предпросмотр предложения поверх текущего расписания: новое — выделено, конфликты и предупреждения — списком справа со ссылками на даты. «Применить» записывает всё в одной транзакции, «Отменить» — ничего не меняет.
- **FR-SCH-8.** (Отменено решением 50.) Если при «Применить» ресурс заняли за время предпросмотра — транзакция откатывается, пользователь видит, что именно занято, и предлагается подобрать заново.
- **FR-SCH-9.** Ручная правка (HTMX, без перезагрузки страницы):
  - изменить группу или сессию, группу бассейна, слот и инструктора, время тренажёра;
  - область действия: «только эта дата» / «эта и все следующие даты курса»;
  - удалить занятие, добавить занятие;
  - на лету показывать нарушения валидатора до сохранения;
  - сохранённая правка становится `pinned` (для «все следующие» — все затронутые бронирования).
- **FR-SCH-10.** Кнопка «Открепить» снимает `pinned` (чтобы движок мог перепланировать).

### 7.5. Изменения курса
- **FR-SCH-11.** Отмена назначения (`cancel_date`) → бронирования этой процедуры с датой ≥ `cancel_date` удаляются. Автоматические — без подтверждения; закреплённые вручную — пользователь видит их список перед подтверждением (решение 33).
- **FR-SCH-12.** Изменение даты окончания программы (`end_date`):
  - раньше — бронирования после новой даты удаляются;
  - позже — на новые даты предлагается «Подобрать» (продлевает текущее время, если оно свободно).
- **FR-SCH-13.** Новое исключение смены (инструктор заболел, не вышел) или новый блок в слоте с бронированиями → система **сама** переставляет затронутые индивидуальные занятия только на затронутые даты (решение 43): в тот же слот к другому свободному инструктору с наименьшей загрузкой (с учётом `preferred_instructor` и напарника), иначе в ближайший свободный слот пациента. Переносятся и закреплённые вручную занятия, и занятия по желанию пациента — в сводке они отмечены отдельно. После перестройки специалист видит сводку «кто → к кому / на какое время, кого поставить не удалось (`INDIVIDUAL_UNPLACED`)» и может поправить любую строку. Отмена исключения не возвращает занятия обратно автоматически — в сводке есть кнопка «Вернуть как было».
- **FR-SCH-18.** Экран **«Расписание групп»** (специалист ФР в любом отделении, админ; пункт меню): расписание групп ЛФК и бассейна (время, длительность, место, действует, добавить занятие) и окна тренажёров (окно, шаг, длительность, вместимость, действует) правятся в вебе, без админки. После сохранения расписание текущих программ с этой группой (в том числе выбранной группой бассейна) или тренажёром — всех отделений — пересобирается сразу, экран показывает список «палата, фамилия, отделение» (решение 48). Занятия, закреплённые вручную в старое время, не трогаются и показываются списком. Новые группы и тренажёры по-прежнему заводятся в справочниках (админка). Группа отделения — только для специалиста этого отделения. Группу у существующего занятия не меняют (иначе у пациентов осталось бы занятие «чужой» группы) — добавляют занятие нужной группе.

### 7.6. Шахматка
- **FR-SCH-14.** Экран «Шахматка на дату»:
  - **слева** — колонки инструкторов в смене (напарники 2/2 — одна колонка с заголовком «A/ B», в ячейках работающий в этот день), строки — слоты сетки;
  - **справа** — таблица тренажёров: колонки — тренажёры, строки — шаги окна (13:00, 13:15, …) и, ниже, время ручных записей вне окна, в ячейке до `capacity` записей (сверх — с пометкой, FR-CAT-4a);
  - сетка выглядит как бумажная шахматка: фиксированный заголовок с инструкторами и колонка времени, свободные ячейки пустые, блоки — серым, индивидуальные — «Nп Фамилия»;
  - ячейка показывает «Nп Фамилия», а для чужого отделения — «Nп ОМР X Фамилия»; пометка `note` дописывается в конце;
  - блоки показываются текстом («Метод. работа», «Эрго общая», «БОС»);
  - навигация: предыдущий и следующий день, выбор даты.
  - на субботу и воскресенье индивидуальные инструкторам не расписываются (решение 56): шахматка выходного показывает только блоки и группы.
- **FR-SCH-15.** Правка ячейки (ответы 18, 19):
  - поставить, перенести или убрать пациента — `rehab`, `admin` (поиск среди активных программ отделений пользователя); врач шахматку только смотрит (решение 46);
  - поставить или убрать блок (тип + подпись) — только `rehab`, `admin`. Блок можно поставить на «ежедневно с даты по дату».
  - Любая правка проходит через тот же валидатор и сразу видна на странице программы и в карте; правка становится `pinned`.
  - Из ячейки пациента — «закрепить за этим инструктором» (ставит `preferred_instructor` программы и перестраивает её индивидуальные занятия).
- **FR-SCH-16.** Чужие пациенты (отделение, в котором пользователь не состоит) видны только как «палата, отделение, фамилия», без перехода к карточке. Публичная шахматка (FR-ACC-5) показывает так всех пациентов.
- **FR-SCH-17.** Отчёт «Загрузка инструкторов» за выбранный период: инструктор → число индивидуальных занятий, рабочих дней, среднее в день; для пар — сумма.

## 8. Выгрузка карты (cards)

### 8.1. Шаблоны
- **FR-CRD-1.** Шаблоны карт пока общие для всех отделений и лежат в коде (`apps/cards/resources/card_templates/`, выбор — решение 40). Модель `CardTemplate` (`department`, `shrm`, `file`, `mapping`) появится вместе с первым отделением, которому нужен свой шаблон. Начальные шаблоны — листы `ШРМ 3`, `ШРМ 4`, `ШРМ 5` из `primary_docs/programm_template.xlsx`, каждый сохраняется отдельным файлом, а примерные данные в нём очищаются.
- **Начальный mapping** сверен в фазе 0 и совпал с файлом заказчика. Хранится в `apps/cards/resources/card_templates/mapping.json`.
- В исходном файле не задан масштаб печати: при 100 % карта не помещается на А4. Поэтому при выделении шаблонов им задаются область печати по краю карты, «вписать в 1 страницу» и центрирование по горизонтали. Время и даты в исходнике хранились дробными числами (`9.15`, `11.09`); в выгрузке это настоящие время и даты Excel (`Ч:ММ`, `ДД.ММ`).

| Элемент | ШРМ 3 | ШРМ 4 | ШРМ 5 |
|---|---|---|---|
| Отделение | N2 | O2 | O2 |
| ФИО | I10 | J10 | J10 |
| «(М) 52 года» | I11 | J11 | J11 |
| Врач (short_name) | J12 | K12 | K12 |
| Типичный день: строки | 4–13 | 4–13 | 4–13 |
| …время / процедура / место | B / C (C:E объединены) / F | то же | то же |
| Даты курса | C17:M17 (11) | C17:Q17 (15) | C18:L18 и C31:L31 (10 + 10) |
| Строки процедур нижнего блока | A18:A32 | A18:A33 | A19:A30 и A32:A43 (дублируются в обоих блоках) |

### 8.2. Заполнение
- **FR-CRD-2.**
  - **Шапка:** ФИО полностью; `({sex}) {age} {год|года|лет}` с правильным склонением; врач; название отделения.
  - **Типичный день:** строки блока — дневные слоты сетки инструкторов по порядку (вечерние не печатаются). Занятие попадает в строку слота, с которым больше всего пересекается по времени; не пересекается ни с одним (вечер, обед) — отдельная строка со своим временем, чтобы не занять чужое окно. В строке — фактическое время начала (значение Excel `time`, формат `Ч:ММ`), `card_label` процедуры, `place`. Несколько занятий в одном слоте — одна строка через «/» («Pablo/st-150»); у занятия, которое начинается позже времени строки, время пишется в подписи («st-150/Имитрон 13:15»). Слот без занятий — **окно**: время слота есть, процедура и место пустые — по окнам инструкторы видят, когда пациент свободен. Для индивидуального занятия место — пусто или `place` из справочника. Дневных слотов больше, чем строк шаблона (10) → выгрузка не выполняется, сообщение со списком.
  - **Даты:** настоящие даты Excel, формат `ДД.ММ`.
  - **Нижний блок:** назначения с `in_card = true` (все виды, включая `CARD_ONLY`), по `Prescription.card_order` (порядок назначений), текст — `card_label`. Строк больше, чем вмещает шаблон → сообщение с количеством, выгрузка не выполняется.
  - Клетки под датами остаются пустыми (отметки от руки). Даты вне `start_date…cancel_date` назначения заштриховываются (серая заливка).
- **FR-CRD-3.** Если расписание по дням отличается от типичного (`DAY_DEVIATION`), перед выгрузкой — предупреждение со списком дат. Выгрузить можно.
- **FR-CRD-4.** Сохраняются оформление шаблона: шрифты, рамки, объединения, логотипы, область печати, ориентация, масштаб. Имя файла: `Программа_{Фамилия}_{ИБ}_{дата поступления}.xlsx`.
- **FR-CRD-5.** Журнал выгрузок: пользователь, время, программа.
- **FR-CRD-6.** (Фаза 4) Кнопка «PDF» — конвертация того же xlsx через LibreOffice в режиме без интерфейса. Если LibreOffice недоступен, кнопка скрыта.
- **Критерии приёмки:**
  - автотест открывает выгрузку через openpyxl и проверяет значения и типы в ячейках по mapping для ШРМ 3/4/5;
  - логотипы присутствуют в файле;
  - **ручная проверка владельцем в MS Excel:** файл открывается без предупреждений и печатается на 1 странице (ШРМ5 — как в шаблоне).

### 8.3. Выгрузка шахматки
- **FR-CRD-7.** Шахматка на дату → `.xlsx`: A1 — дата, строка 1 — фамилии (пары «A/ B»), колонка A — интервалы слотов, справа через пустую колонку — тренажёры. Альбомная ориентация, вписать в 1 страницу по ширине.

## 9. Импорт справочников и текущей шахматки (exchange)

- **FR-EXC-1.** Импорт `lfk.xlsx` и `basseyn.xlsx` через веб (роль `admin`/`rehab`): предпросмотр «будет добавлено / изменено / без изменений» → подтверждение. Повторный импорт не создаёт дублей.
- **FR-EXC-2.** Разовый импорт текущей шахматки: пользователь выбирает файл и лист (дату). Разбор:
  - строка 1 → колонки инструкторов (`"A/ B"` → пара, сопоставление со справочником по `short_name`, несопоставленные — выбрать вручную);
  - колонка A → слоты по началу интервала (тексты вида `9:10-9:40`, а для вечерних — числа `18`, `18.399999…` → 18:00, 18:40);
  - **ячейка:** `Метод. Работа` → блок; название группы или `БОС` → блок `GROUP_LEAD`/`BOS`; иначе — одна или несколько записей по шаблону `(?P<room>\d+[а-я]?)п\s+(?:(?P<dep>ОМР\s?\d+)\s+)?(?P<name>[А-ЯЁ][а-яё-]+)(?P<note>.*)`, где пометки `инд`, `art`, `Мото-Л`, `(шар)` уходят в `note`;
  - правая таблица (колонки с заголовками тренажёров) — записи на тренажёры; время строк не берётся из колонки A.
- **FR-EXC-3.** Найденные записи сопоставляются с активными программами по палате + фамилии. Неоднозначные или ненайденные → таблица ручного сопоставления (или «пропустить»). Подтверждённые записи становятся `pinned`-бронированиями `source = import` **на выбранную дату и все следующие даты курса** пациента (если ресурс свободен), а блоки — на выбранную дату.
- **FR-EXC-4.** Отчёт импорта: сколько ячеек разобрано, сколько поставлено, список нераспознанного с адресами ячеек.
- **Тест-фикстура:** обезличенная копия листа `5,10` из `instructions_schedule.xlsx` (фамилии заменены), с проверкой разбора всех типов ячеек.
