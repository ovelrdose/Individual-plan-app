# Руководство администратора

Как установить сервис, завести пользователей, вести справочники и делать резервные копии.

> Установка на сервер (виртуальная машина, пакеты, gunicorn, nginx, HTTPS, перенос базы, бэкап по расписанию) — в [deploy.md](deploy.md). Как заполнять входные файлы — в [input-files.md](input-files.md). Ниже — работа с уже установленным сервисом. Команды `manage.py` на сервере запускаются так: `cd /opt/omr4/app && sudo -u omr4 /opt/omr4/venv/bin/python manage.py …`.

## 1. Первый запуск

Сервер, `.env` и перенос базы описаны в [deploy.md](deploy.md), шаги 1–7. Если база переносится копией с машины разработки, команды ниже не нужны. Если база собирается с нуля, выполните их по порядку:

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py load_initial_catalog
.venv/bin/python manage.py create_users
.venv/bin/python manage.py load_board_instructors --since 2026-09-01
```

| Команда | Что делает |
|---|---|
| `migrate` | Создаёт таблицы |
| `load_initial_catalog` | Отделение ОМР № 4, процедуры, групповые занятия, тренажёры, сетку слотов |
| `create_users` | Врача, специалиста ФР и администратора, пароли спросит |
| `load_board_instructors` | Инструкторов, пары 2/2 и их распорядок из `primary_docs/instructions_schedule.xlsx` |

`--since` — день, с которого действуют смены. Кто из пары 2/2 в какой день работает, в файле не видно: по умолчанию с этой даты работает первый в подписи. Поправьте на экране «Смены».

Все команды можно запускать повторно: они ничего не дублируют.

**Текущие пациенты.** Чтобы завести пациентов, которые уже лечатся, по сводкам постов, положите сводки в `primary_docs/` и выполните `load_current_patients`. Из сводок берутся ФИО, ИБ, возраст, пол, даты поступления и выписки и врач. Команда **удаляет всех пациентов** в системе и перед этим спрашивает подтверждение. Врачи из сводки заводятся пользователями без пароля: задайте им пароль в «Пользователях».

### Команда `create_users`

```bash
.venv/bin/python manage.py create_users                       # пароли спросит для каждого
.venv/bin/python manage.py create_users --password 'Пароль…'  # один пароль всем, без вопросов
.venv/bin/python manage.py create_users \
    --doctor ivanova --doctor-name 'Иванова А.А.' \
    --rehab petrova  --rehab-name  'Петрова Б.Б.' \
    --admin admin
```

| Пользователь | Логин по умолчанию | Права |
|---|---|---|
| Врач | `doctor` | Шаблон «Врач» в ОМР № 4: программы и лечащий врач |
| Специалист ФР (инструктор) | `rehab` | Шаблон «Специалист ФР» в ОМР № 4: программы с удалением, расписание, групповые занятия, смены, справочники |
| Администратор | `admin` | Суперпользователь: все права |

- **Пароль:** не короче 8 символов, не только цифры, не слишком простой и не похожий на логин.
- **Уже существующие пользователи** не меняются: ни пароль, ни права. Отделение ОМР № 4 создаётся, если его нет.
- **`--doctor-name`** — фамилия и инициалы врача. Они печатаются в карте как лечащий врач, поэтому для врача их стоит задать сразу.

## 2. Пользователи

Меню с вашим именем → **«Пользователи»** (нужно право «Пользователи и отделения»). Ролей нет: у каждого пользователя свои галочки прав и свои отделения.

**Новый пользователь:** «Добавить пользователя».

1. Логин, фамилия, имя и пароль.
2. **Отделения** — программы каких отделений он видит. Права действуют только в них.
3. **Права:** нажмите шаблон **«Врач»**, **«Специалист ФР»** или **«Администратор»** — он проставит типичные галочки. Потом их можно поправить.
4. **«Лечащий врач»** — его можно выбрать врачом программы, и он печатается в карте. Тогда обязательно заполните **«Фамилия и инициалы»** (`Иванова А.А.`).

| Право | Что даёт |
|---|---|
| Программы: создавать и править | Загрузить лист назначений, создать и править программу, отметить выбытие, выбрать время группы на весь курс |
| Программы: удалять | Удалить программу целиком |
| Расписание пациентов | Ставить индивидуальные в расписание, выбирать группу бассейна и время группы на весь курс, править время групп и тренажёров пациента в отдельные дни |
| Групповые занятия | Экран «Групповые занятия»: разделы, новые группы и их расписание, тренажёры |
| Инструкторы | Смены, распорядок, загрузка инструкторов |
| Справочники | Экран «Справочники»: процедуры, инструкторы, сетка слотов (просмотр) |
| Пользователи и отделения | Этот экран, вкладка «Отделения», снятие блокировки входа, журнал выгрузок карт в «Справочниках»; видит все отделения |

Без галочек пользователь только смотрит программы своих отделений и скачивает карты.

**«Администрирование»** (админка Django, `/admin/`) — только у суперпользователя (`admin` из `create_users`): это технический инструмент сервера. Всё, что нужно в работе, — на экранах сервиса: «Справочники», «Групповые занятия», «Пользователи». Галочки прав админку не открывают; «Статус персонала» ставится сам только суперпользователю.

**Новый пароль:** «Пользователи» → кнопка **«Пароль»** у пользователя. Старый пароль не нужен. Сменить пароль пользователь может и сам: меню → «Сменить пароль».

**Уволился сотрудник** — откройте его и снимите **«Учётная запись действует»**. Пользователи не удаляются: по ним подписаны программы и журнал изменений.

Себе нельзя снять право «Пользователи и отделения» и нельзя отключить себя — чтобы не остаться без администратора. Суперпользователя (`admin` из `create_users`) правит только суперпользователь.

**Блокировка входа:** после 10 неверных паролей логин блокируется на 15 минут. В списке пользователей у него пометка **«вход заблокирован до ЧЧ:ММ»**; кнопка **«Снять блокировку»** снимает её сразу.

## 3. Отделение

Отделения — вкладка **«Отделения»** экрана «Пользователи» (право «Пользователи и отделения»). В рабочей базе одно отделение — **ОМР № 4**. Шестерёнка у отделения открывает окно:

- название и код;
- длительность курса в календарных днях, считая день поступления, — отдельно для ШРМ 3, 4, 5 и УК (по умолчанию 11, 15, 20 и 15; УК — курс как у ШРМ 4, карта печатается на шаблоне ШРМ 4);
- сколько индивидуальных занятий в день можно назначить, не больше (2).

**«Новое отделение»** — без изменения кода. **«Удалить»**: отделение без программ, сотрудников и своих процедур удаляется совсем; иначе уходит в архив (его сотрудники перестают его видеть, программы сохраняются) — но только если в нём нет текущих программ. Архив свёрнут внизу таблицы, оттуда отделение можно вернуть. Пользователь может состоять в нескольких отделениях, тогда в шапке появится выбор отделения.

## 4. Справочники

Справочники ведутся на экранах сервиса (админка — только у суперпользователя):

| Где | Что там |
|---|---|
| **«Справочники»** → «Процедуры» (право «Справочники») | Все процедуры, кроме групп: индивидуальное, «только строка в карте», «Бассейн» без группы, вечернее индивидуальное (Мото-Л, Артромот), процедуры тренажёров. Название, подпись в карте, **синонимы** (как процедура пишется в листах назначений), вид, длительность, место, отделение. Фильтр по виду и поиск. Если строка листа не распознаётся, добавьте её написание в синонимы нужной процедуры. У назначавшейся процедуры не меняются вид, признаки («Бассейн» без группы, вечернее индивидуальное) и отделение — заведите новую |
| «Справочники» → «Инструкторы» | Фамилия «как в расписании», ФИО, напарник по 2/2 (связь ставится с обеих сторон), порядок колонок. Смены и распорядок — на экранах «Смены» и «Распорядок» |
| «Справочники» → «Сетка слотов» | Время индивидуальных занятий — только просмотр |
| «Справочники» → «Журнал выгрузок карт» (право «Пользователи и отделения») | Кто и когда скачал карту пациента: фильтр по дате, поиск по фамилии |
| **«Групповые занятия»** (право «Групповые занятия», `docs/user-guide.md`, раздел 4) | Разделы, группы и их время, тренажёры: окно, шаг, длительность, вместимость, название, подпись и синонимы. Там же видно, у каких пациентов изменилось расписание |
| «Пользователи» → «Отделения» | Раздел 3 |

**Удаление везде одинаковое.** Шестерёнка → окно → «Удалить» → подтверждение в окне. Ни разу не использованная запись удаляется совсем (автор — в журнале изменений). Использованная уходит **в архив** — свёрнутый блок «В архиве (N)» внизу таблицы, оттуда её можно **«Вернуть из архива»**. Галочек «действует» / «работает» в формах нет.

- **Процедура в архиве** пропадает из поиска и из распознавания листа. «Только строка в карте» остаётся у назначений. Процедура тренажёра уходит в архив вместе с тренажёром: у текущих пациентов занятия на нём снимаются, в программе — красное «тренажёр выключен». Индивидуальное, «Бассейн» без группы и вечернее индивидуальное, пока они назначены текущим пациентам, в архив не уходят — окно перечислит пациентов.
- **Инструктор в архиве:** с сегодняшнего дня его нет в сменах и расписании, его пациенты на сегодня и завтра уходят в «Не распределены» (окно их перечислит), шаблон смены, распорядок и «Ведение группы» заканчиваются сегодня, пара 2/2 разрывается — напарник работает один. Вернули из архива — задайте шаблон смены на экране «Смены».

### Шаблоны карт

Шаблоны ШРМ 3/4/5 лежат в `apps/cards/resources/card_templates/`, адреса ячеек — в `mapping.json`. Если заказчик изменил `primary_docs/programm_template.xlsx`, пересоберите шаблоны:

```bash
.venv/bin/python manage.py extract_card_templates
```


## 5. Резервные копии и обновление

Ежедневная копия базы (`pg_dump`, хранится 30 дней), восстановление и обновление версии описаны в [deploy.md](deploy.md), шаги 10 и 12. Копии содержат персональные данные пациентов: храните их только на серверах клиники (152-ФЗ).

## 6. Если что-то не так

| Признак | Что делать |
|---|---|
| Строка листа назначений не распознаётся | Добавьте её написание в синонимы процедуры (раздел 4) |
| Инструктор не появляется в расписании | Проверьте, не в архиве ли он («Справочники» → «Инструкторы»), и смену на экране «Смены» |
| `/board/` не открывается с компьютера в коридоре | Добавьте сеть этого компьютера в `PUBLIC_BOARD_NETWORKS` и перезапустите сервис |
| Пользователь не может войти | Проверьте «Учётная запись действует» и пометку «вход заблокирован» в списке пользователей («Снять блокировку») |
| Страницы не обновляются сами | Обновление идёт через `/events/`. За прокси для этого адреса нужно отключить буферизацию |
