# Устройство системы

Документ для разработчика и ИИ-помощника, который будет вести проект: что где лежит, за что отвечает каждый модуль, как данные проходят через систему и какие правила нельзя нарушать. Требования и номера решений — в [TZ.md](TZ.md), соглашения по коду и глоссарий — в [CLAUDE.md](../CLAUDE.md), установка — в [deploy.md](deploy.md).

Номера вида `FR-SCH-10` и «решение 83» — ссылки на [TZ.md](TZ.md): требования (`FR-…`, `NFR-…`) и таблица решений в §13. В коде на них ссылаются комментарии — по ним удобно искать: `grep -rn "решение 81" apps`.

---

## 1. Что делает система

Веб-сервис отделения медицинской реабилитации (первое — ОМР № 4). Три задачи:

1. **Индивидуальная программа** пациента (`Program`) — из листа назначений врача (`.docx`/`.doc`): данные пациента, курс, назначения (`Prescription`).
2. **Расписание**:
   - группы ЛФК, группы ДС, бассейн и тренажёры система ставит сама **на весь курс** (движок `scheduling/domain/engine.py`);
   - индивидуальные занятия с инструкторами — **шахматка на день вперёд** (сегодня и следующий будний день), только по будням (`scheduling/board_days.py`, `domain/board_day.py`).
3. **Карта** — `.xlsx` по шаблону заказчика для печати из MS Excel. Отметки о проведённых занятиях ставят от руки.

Интеграций с МИС нет. Диагноз в систему не переносится (решение 70). На экране шахматка называется «Расписание», в коде — `board`.

## 2. Стек и среда

| Что | Чем |
|---|---|
| Язык, фреймворк | Python 3.12, Django 5.2 LTS |
| База | PostgreSQL 16: `ArrayField`, `ExclusionConstraint` (`btree_gist`), advisory lock, `LISTEN/NOTIFY` |
| Интерфейс | Шаблоны Django + HTMX (+ `hx-boost` на `<body>`) + Alpine.js, Bootstrap 5 — всё локально в `static/vendor/` |
| Файлы | openpyxl (карта, шахматка, справочники), python-docx (лист назначений, сводки), LibreOffice (`.doc` → `.docx`) |
| Журнал | django-simple-history: у ключевых моделей `history = HistoricalRecords()` |
| Тесты, стиль | pytest + pytest-django на настоящем PostgreSQL; ruff (линтер и форматтер, строка 100) |
| Прод | ВМ Ubuntu 24.04: venv + gunicorn (systemd) + nginx + PostgreSQL; два контура — тест и прод ([deploy.md](deploy.md)) |

Точные версии — `pyproject.toml` (`[dependency-groups]`, `==`); прод ставится из `requirements.txt`, собранного из группы `prod`. Все настройки — `config/settings.py`, значения — из `.env` (`.env.example` для разработки, `deploy/env.production.example` для прода).

## 4. Слои и правила зависимостей

```
templates (HTMX)  →  views.py (тонкие)  →  services.py (права + правила + транзакции)  →  models.py
                                                     ↓ dataclass                ↑ результат
                                               domain/ (чистый Python)
```

- **`domain/`, `apps/*/domain.py`, `apps/cards/xlsx/`, разборщики `exchange/*`** — без импортов Django. На входе dataclass, на выходе результат. Это то, что проще всего тестировать и где живут алгоритмы. Покрытие этих модулей — не ниже 90 %.
- **`services.py`** — единственное место, где меняются данные. Здесь проверяются права (`require_right`, `require_*`), бизнес-правила, берутся блокировки, вызывается `replan`. Сервис сохраняет модель с историей через `instance._history_user = user`, чтобы автор попал в журнал и вне веб-запроса.
- **`views.py`** — разбор запроса, вызов сервиса, рендер. Ошибка сервиса — отдельное исключение с русским текстом (`ProgramsError`, `ScheduleError`, `CatalogError`, `StaffError`, `EditError`/`BoardError`, `CardRenderError`, `SheetError`, …); вьюха показывает её в том же фрагменте.
- **Шаблоны** — Bootstrap + HTMX. Действие возвращает фрагмент целиком (`hx-swap="outerHTML"`), ошибки форм — в том же фрагменте со статусом 200. Соседние части страницы обновляются через `hx-swap-oob`.

Циклические импорты между приложениями (`programs` ↔ `catalog` ↔ `scheduling`) обходятся импортом внутри функции с комментарием «иначе цикл».

## 5. Модель данных

### 5.1. Отделения и пользователи

| Модель | Ключевое | Заметки |
|---|---|---|
| `org.Department` | `name`, `code`, `course_days` (JSON: ШРМ 3/4/5/УК → дни), `max_individual_per_day`, `is_active` | Программы, сотрудники и свои процедуры привязаны к отделению. Архив — только без текущих программ |
| `accounts.User` | `rights` (`ArrayField` из `Right`), `is_attending_doctor`, `short_name` («Иванова А.А.» — печатается в карте), `departments` через `Membership` | Ролей нет; `Preset` (Врач / Специалист ФР / Администратор) — только шаблон галочек на форме |
| `accounts.LoginFailure` | `username`, `created_at` | Блокировка входа: считается по логину, в БД — одинаково во всех процессах gunicorn |

### 5.2. Справочники (`catalog`)

| Модель | Ключевое | Заметки |
|---|---|---|
| `Procedure` | `name`, `card_label` (как в карте), `synonyms` (как пишут в листе), `kind` (`ProcedureKind`), `default_duration_min` (≥ 1), `place`, `department` (пусто — общая), `section`, `equipment`, `group_choice` («Бассейн» без группы), `evening_individual` (Мото-Л, Артромот), `is_active` | Название уникально в отделении без учёта регистра (`Lower`). У назначавшейся процедуры нельзя менять вид, признаки и отделение |
| `ProcedureKind` | `LFK_GROUP`, `DS_GROUP`, `POOL`, `INDIVIDUAL`, `EQUIPMENT`, `CARD_ONLY` | Вся логика расписания работает по `kind`. `CARD_ONLY` — только строка в карте без времени |
| `Section` | `name`, `behavior` (= `kind` групп раздела: «Ведёт инструктор» / «Без инструктора» / «Бассейн»), `order` | Вкладка экрана «Групповые занятия» (решение 82). Группа переносится только в раздел того же поведения |
| `GroupSession` | `procedure` (группа), `start_time`, `duration_min`, `place`, `is_active` | Ежедневное занятие группы; расписание групп одинаковое каждый день недели |
| `Equipment` | `window_start…window_end` (13:00–15:00), `step_min`, `duration_min`, `capacity`, `is_active` | У тренажёра одна процедура вида `EQUIPMENT` |
| `InstructorSlot` | `start` (уникально), `end`, `is_evening` | Сетка слотов индивидуальных; вечерние (18:00, 18:40, 19:20) — только у инструкторов 2/2 |

### 5.3. Инструкторы (`staff`)

| Модель | Ключевое | Заметки |
|---|---|---|
| `Instructor` | `short_name` (как в шахматке), `full_name`, `partner` (пара 2/2, симметрию держит `set_partner`), `display_order`, `is_active` | Архив: с сегодняшнего дня нет в сменах и шахматке; прошлое видно (`teams_with`) |
| `ShiftPattern` | `pattern` (2/2, 5/2, каждый день), `anchor_date`, `valid_from…valid_to` | Периоды одного инструктора не пересекаются — `ExclusionConstraint` |
| `ShiftException` | `date`, `is_working`, `reason` | Больничный, подмена — поверх шаблона |
| `InstructorDuty` | `slot`, `kind` (метод. работа, ведение группы, БОС, прочее), `group_session`, период | Постоянный распорядок; периоды по слоту не пересекаются (`ExclusionConstraint`) |
| `InstructorBlock` | `date`, `slot`, `kind` (+ `CLEAR` — снять распорядок в день) | Разовый блок на дату |

Часы смены (`staff/domain.shift_hours`): 2/2 — 8:00–20:00, остальные — 8:00–17:00. Распорядок ставится только в часы смены.

### 5.4. Программы (`programs`)

| Модель | Ключевое | Заметки |
|---|---|---|

### 5.5. Расписание (`scheduling`)

| Модель | Ключевое | Заметки |
|---|---|---|
| `Booking` | `program`, `prescription`, `procedure`, `kind`, `date`, `start…end`, `group_session`, `equipment`, `instructor`+`slot` (только у индивидуальных), `note` (пометка), `source` (подбор/вручную/импорт), `pinned`, `version` | Одно занятие пациента в дату. **Пациент не в двух местах** — `ExclusionConstraint` по `(program, период)`. ## 6. Права

Решение 79: у пользователя набор галочек `User.rights` (общих для всех его отделений) и признак `is_attending_doctor`. Проверки — **только** через `apps/accounts/access.py`:

| Функция | Что |
|---|---|
| `has_right(user, right, department=None)` / `require_right` | Есть ли право (в отделении) |
| `departments_for(user)` | Отделения, которые пользователь видит |
| `departments_with(user, right)` | Отделения, где у него есть право |
| `is_admin(user)` | Суперпользователь или право `users` — видит все отделения |
| `doctors_for`, `is_attending_doctor` | Кого можно выбрать лечащим врачом |
| `current_department`, `select_department` | Выбранное в шапке отделение |

| Право (`Right`) | Что даёт |
|---|---|
| `programs_edit` | Создать и править программу, импорт листа, выбытие, время групп |
| `programs_delete` | Удалить программу |
| `schedule` | Шахматка, группа бассейна, правка групп и тренажёров пациента по дням |
| `group_schedule` | Экран «Групповые занятия» |
| `staff` | Смены, распорядок, загрузка инструкторов |
| `catalog` | Экран «Справочники» |
| `users` | Пользователи, отделения, журнал выгрузок; видит все отделения |

Без галочек — просмотр программ своих отделений и скачивание карт. Пациентов чужого отделения в шахматке видно как «9п ОМР 1 Фамилия», без ссылки; в сообщениях сервисов фамилии чужих пациентов не называются (`for_viewer`, `_holders_text`).

Все страницы закрыты входом (`LoginRequiredMiddleware`); открытая помечается `@login_not_required` — это вход и публичная шахматка `/board/` (её сети — `PUBLIC_BOARD_NETWORKS`). Админка Django — только суперпользователю: сигнал `accounts/signals.py` держит `is_staff = is_superuser`, групп и прав Django нет.

```
файл .doc ─ word_doc.doc_to_docx (LibreOffice) ─┐
файл .docx ─────────────────────────────────────┴→ prescription_sheet.parse_sheet → Sheet (шапка, строки, предупреждения)
                                                                ↓
             exchange.services.import_prescription_sheet(user, sheet, plan=…)
               1. find_duplicates — тот же пациент с пересекающимся курсом → DuplicateProgramError
                  (экран: открыть существующую / обновить её / всё равно создать)
               2. find_previous_courses — пациент лечился раньше → PreviousCoursesFound, пока не выбран Plan
                  (новый лист / прошлый план / это другой пациент); лист ждёт в сессии (exchange/views.py)
               3. Program + Prescription по строкам: matching.match_with_typos → Procedure или None
                  (нераспознанное — строка с raw_text, подсвечивается); предупреждения → import_warnings
               4. replan(program)
```

- **Разбор листа** (`prescription_sheet.py`) терпим к ручному Word: шапка — по подписям полей, таблица — по ячейке «Физиотерапия», даты назначения слева, отмены справа. Ячейка со списком групп распознаётся по дефисам или заголовку («Групповые занятия ЛФК», «ЛФК в группе…»); без того и другого все строки ячейки — одно назначение ([input-files.md](input-files.md)).
- **Сопоставление** (`matching.py`): синоним входит в строку, при нескольких — самый длинный; бассейн — по группе (верхн/нижн/спин), без группы — общий «Бассейн»; группы ДС — последними (`FALLBACK_KINDS`); опечатка в одну букву — `match_with_typos`.
- **Время группы из листа** («Спина в 16:30») сразу становится `Prescription.group_session`.

### 7.2. Обновление программы из новой версии листа (FR-IMP-15)

`exchange.services.preview_sheet_update` → «было → стало» без записи; `apply_sheet_update` применяет. Оба идут через общий `_merge`: строки сопоставляются по тексту, затем по процедуре и **обновляются, а не пересоздаются** — прошедшие занятия, `pool_group`, `group_session`, закреплённые занятия и место в шахматке остаются. Строка без времени выбор времени не сбрасывает. Пропавшая строка: начатая — отменяется с завтра, не начатая — удаляется. Разобранный лист ждёт в сессии с ключом `program`.

### 7.3. Любое изменение → `replan`

`apps/scheduling/services.replan(program)` — сердце системы. Вызывается **после импорта и любого изменения** назначений, курса, выбытия, расписания групп, окна тренажёра, архива процедуры. Специалисту не нужно нажимать «пересчитать».

```
replan(program):
  блокировки: программа → тренажёры → инструкторы → шахматки (board_days.lock)
  1. индивидуальные в составленных шахматках (сегодня и дальше) временно снимаются,
     их места запоминаются (seats) — группы встают по своему расписанию
  2. незакреплённые занятия групп, бассейна и тренажёров удаляются (без журнала, пакетом);
     пометки тренажёров запоминаются (_equipment_notes)
  3. закреплённые, ставшие невалидными (вне курса, вне дат назначения, занятие группы выключено
     или перенесено), удаляются с записью в журнал
  4. Snapshot (потребности, занятость пациента, загрузка тренажёров другими, мягкая занятость
     индивидуальными) → domain.engine.propose → Proposal (placements + issues)
  5. bulk_create новых занятий (тренажёр получает пометку своего дня или ближайшего прошлого);
     program.schedule_issues = issues   # сохраняется, только если изменились (без лишней строки журнала)
  6. board_days.sync_program(program, seats) — сверка с составленными шахматками
  7. live.publish(program:ID, board:сегодня, board:завтра)
```

После пересборки `replan(program)` вызывает `refill_equipment` для тренажёров программы: если с завтрашнего дня на тренажёре есть свободное время (`_free_equipment_slots` — пары тренажёр × дата), программы с конфликтом `EQUIPMENT_UNPLACED` (отбираются в SQL по `schedule_issues`; нет ждущих — сразу выход) пересобираются по очереди поступления с `refill=False, keep_today=True` — только те, у кого свободная пара совпадает с днём без тренажёра (`_missing_equipment`), и только пока свободное время остаётся: пересборка дорогая, а место после правки обычно одно — сегодняшние тренажёры не меняются, на сегодня ждущих ставит специалист (FR-SCH-11a). Ждущих блокируют с `skip_locked`: программу, которую правит другой запрос, он пересоберёт сам. `_replan_current` идёт по программам тоже по очереди поступления с `refill=False` и добирает ждущих один раз в конце; `replan_for_equipment` пересобирает все программы тренажёра и `refill` не зовёт.

Групповые правки (`replan_for_group`, `replan_for_equipment`) пересобирают все текущие программы с этой группой или тренажёром; итог для экрана — `Rescheduled` (у кого что изменилось, кто ушёл в «Не распределены»). `watch_displaced` — общий механизм «снимок шахматок до и после», чтобы назвать вытесненные индивидуальные.

### 7.3a. Журнал расписания (`journal.py`, FR-SCH-19)

Записи не пишутся в местах изменений — их слишком много. Действие открывает `journal.action(текст, user)` (у сервисов с пользователем первым аргументом — декоратор `@journal.logged("…")` под `@transaction.atomic`); всё, что меняет пациента, сначала зовёт `journal.watch(programs)` — запоминается его состояние: индивидуальные в составленных шахматках с сегодня и тренажёры с сегодня до конца курса (строки «Волков 9:10, Не распределены», «13:00», «Отменён»). Точки `watch`: `manual.lock_program` (вся ручная правка), `programs.services._lock`, `services._replan`, `board_days._recompute`. При выходе из внешнего действия состояние сравнивается (`domain/journal.changes`): подряд идущие даты с одинаковым «было → стало» — одна запись; новая шахматка сравнивается с днём-источником (`journal.new_board`).

- Пациент относится к действию, в котором его впервые тронули: правка специалиста — от него, ждущий из `refill_equipment` — от системы. `replan` открывает действие только запасное (`fallback`), вложенные действия того же пользователя поглощаются внешним.
- Причины: `board_day.plan_day` возвращает `PatientDay.why` (перенос, напарник, кто не работает, чем занят пациент — `Patient.busy_labels`, почему эта ячейка, что мешало), `engine.propose` — `Proposal.reasons[(назначение, дата)]` (основное время, замена, почему не поставлен; `Busy.label`). Их передают `journal.explain`; подтверждённые нарушения и причина специалиста — `journal.note` (`manual.journal_reason`).
- Новый код, который меняет занятия или блоки шахматки, должен звать `watch` до изменения — иначе изменение в журнал не попадёт.

### 7.4. Движок подбора (`domain/engine.py`)

Жадный подбор на весь курс. Порядок шагов — `STEP_ORDER`: группы ЛФК → группы ДС → бассейн → тренажёры. Внутри шага сначала группы с меньшим выбором времени (у выбранного времени выбор = 1), чтобы результат не зависел от порядка строк в листе.

Идея одна: выбрать **одно время на весь курс** — то, что подходит в наибольшее число дней; в дни, где не подходит, взять замену на день (предупреждение), нет замены — день пустой (конфликт). Среди равных: меньше пересечений с индивидуальными («мягкая» занятость), прежнее время, раннее.

- `per_day` у группы — сколько раз в день каждая группа; больше, чем занятий в расписании, не поставить (`GROUP_FREQUENCY`).
- Выбранное время (`Prescription.group_session`, решение 81) — основное для первого занятия дня без сравнения; без выбора — предупреждение `GROUP_TIME_AUTO` на экране.
- «Бассейн» без группы без выбранной `pool_group` — `POOL_TYPE_REQUIRED` (красное).
- Тренажёры — шаги окна, вместимость считается вместе с занятиями других пациентов (`EquipmentLoad`).
- Пересекать занятия пациента нельзя никогда — это ещё и ограничение базы.

### 7.5. Шахматка на день (`board_days.py`, `domain/board_day.py`)

Шахматка на **сегодня** (в будни) и **следующий будний день** есть всегда. Отдельного задания на сервере нет: `ensure_boards()` вызывается при первом обращении к расписанию в новый день и создаёт недостающие.

```
create_board(day):                   # уже есть BoardDay(day) — ничего не делает
  основа — предыдущая составленная шахматка
  domain.board_day.plan_day(...):
    1. перенос: пациент встаёт туда, где стоял (тот же инструктор; у пары 2/2 — работающий
       напарник; то же время; та же пометка). Нельзя — в «Не распределены»
    2. автопостановка недостающих (новые пациенты): колонка, где меньше всего пациентов,
       затем раннее время, затем порядок колонок; в ячейку автоматически — не больше одного;
       без выбранного времени группы — по возможности мимо всех занятий этой группы
    правила: два индивидуальных пациента не подряд; пациент не в двух местах;
    Мото-Л / Артромот — одно из индивидуальных в вечернем слоте у 2/2
  выписанные уходят; первой шахматки нет — все раскладываются как новые
```

- `sync_program(program, seats)` — после `replan` (пациента без индивидуальных и Мото-Л, которого в шахматках нет, пропускает — `_on_boards`): лишние занятия убираются, ставшие невозможными — в «Не распределены», новые — в **завтрашнюю** шахматку автоматически. В сегодняшнюю сами не ставятся даже новые пациенты (`auto=False`): их ставит специалист.
- `propagate(program, day)` — правка сегодняшней шахматки переходит на завтрашнюю, если там пациента отдельно не правили (`BoardPatient.edited`).
- `fit_trainers` — освободить время индивидуального от тренажёра, поставленного подбором: тренажёр сдвигается в своём окне.
- `lock()` — `pg_advisory_xact_lock`: все изменения шахматок под одной блокировкой, два пользователя не составят один день дважды.
- Колонки шахматки — команды инструкторов (`staff.services.build_teams`; для прошлых дат `teams_with` добавляет архивных, у кого были занятия). Кто работает и что занято в слоте — `staff.services.instructor_calendars` → `staff.domain.InstructorCalendar`.

### 7.6. Ручная правка

| Где | Модуль | Что |
|---|---|---|
| Шахматка: индивидуальные | `board.py` — `place_patient`, `move_patient`, `remove_patient`, `set_note` | Поставить, перенести (и перетаскиванием), убрать в «Отменены», пометка. Только сегодня и завтра. Правка сегодня → `propagate` на завтра |
| Шахматка: тренажёры | `board.py` — `move_equipment`, `place_equipment`, `hold_equipment`, `set_equipment_note`; блоки — `equipment_holds` | Перенос, постановка из блока и снятие в блок «Не распределены» / «Отменены» — на эту дату и следующие (`manual.edit_booking(strict=True)`: дни с другим закреплённым временем не трогаются; сверх вместимости и вне окна — на все дни после подтверждения `confirmed`, причина необязательна, предупреждения дней сводятся `manual.by_days`, решение 85). Закреплённые записи в сетке — значок булавки. Блоки считаются при показе: назначено − поставлено − `RemovedSession`; снятые хранятся `RemovedSession` с `kind`. Пометка — с этой даты на все следующие записи назначения, без закрепления (FR-SCH-11a) |
| Шахматка: инструкторы | `board.py` — `add_block`, `add_duty`, `end_duty`, `clear_block`, `paint_duty`; `staff_changes.set_not_working` | Блок на дату, постоянный распорядок, «не работает»; экран «Распорядок» — `paint_duty` поверх тех же функций |
| Страница программы: группы и тренажёры | `manual.py` — `edit_booking`, `remove_booking`, `restore_date`, `unpin` | «Эта дата» или «эта и все следующие»; правка закрепляет (`pinned`), убранное запоминается (`RemovedSession`) |
| Страница программы: время групп | `services.choose_group_time`, `choose_pool_group` | Время группы на весь курс; группа бассейна. Выбор сохраняется, даже если лёг на индивидуальное, — оно уходит в «Не распределены» |

Каждая правка проходит **единый валидатор** `domain/validate.validate` (пациент занят, слот закрыт, инструктор не работает, два индивидуальных подряд, тренажёр полон / вне окна). Нарушения бывают неустранимые (сохранить нельзя), с пометкой (нужна причина — `ConfirmationRequired`) и с подтверждением.

### 7.7. Смены и распорядок → «Не распределены»

`apps/scheduling/staff_changes.py`: изменилась смена (клик в «Сменах», «не работает» в шахматке), распорядок или блок — `rebuild(instructor, start, end)` переносит его пациентов в составленных шахматках, которых теперь нельзя вести, в «Не распределены». Специалист ставит их сам; автоматической перестройки нет.

Выключили или перенесли занятие группы — `end_group_leads`: «Ведение группы» на него заканчивается сегодня, будущие блоки удаляются, окно называет, у кого освободился слот.

### 7.8. Выбытие и повторный курс

- `programs.services.withdraw(day)` — с этой даты занятий нет, пациент уходит из шахматок и их блоков; прошлое не меняется. `restore` — пока плановый курс не закончился: группы и тренажёры подбираются заново, в завтрашнюю шахматку пациент встаёт сам, в сегодняшнюю — в «Не распределены». Всё остальное делает `replan` по `gaps` и `withdrawn_on(day)`.
- Повторный курс (FR-PRG-10): `Program.previous`; `find_previous_courses`, `patient_courses`, `link_previous`, `copy_plan` («Взять прошлый план» — назначения без дат, группа бассейна и время групп, если ещё действуют; процедура из архива приходит нераспознанной строкой).

### 7.9. Справочники: удаление и архив (решения 82, 83)

Одно правило для процедур, групп, времён групп, разделов, тренажёров, инструкторов и отделений:

- **ни разу не использованное** — удаляется совсем (автор — в журнале). Проверяются **все** внешние ключи, включая `related_name="+"` (`procedure_is_used`, `group_is_used`, `session_is_used`, `equipment_is_used`, `instructor_is_used`, `department_is_used`), повторно — под `select_for_update`;
- **использованное** — в архив (`is_active=False`) со всеми последствиями: пересборка текущих программ, «Ведение группы» заканчивается сегодня, архив инструктора — его пациенты на сегодня и завтра в «Не распределены», смена и распорядок заканчиваются сегодня, пара 2/2 разрывается;
- **«Вернуть из архива»**; галочек «действует» в формах нет.

Защиты: индивидуальное, «Бассейн» без группы и вечернее индивидуальное, пока назначены текущим пациентам, в архив не уходят (`_GUARDED`); отделение с текущими программами — тоже.

Экраны справочников устроены одинаково: таблица только для чтения + модальное окно по шестерёнке (`#edit-modal`, содержимое — `.side-panel`, открытие/закрытие — `static/js/prescriptions.js`). Действие возвращает содержимое окна, таблицу — через `hx-swap-oob`; подтверждение удаления — шаг в окне (`includes/_confirm_delete.html`). Окно помещается без прокрутки: поля попарно в строку.

## 8. Инварианты и блокировки

| Правило | Где держится |
|---|---|
| Пациент не в двух местах в одно время | `Booking` `ExclusionConstraint` (`btree_gist`) + валидатор + движок |
| Инструктор и слот — только у индивидуальных | `Booking` `CheckConstraint` |
| Периоды смен и распорядка одного инструктора не пересекаются | `ExclusionConstraint` в `staff.models` |
| Порядок блокировок: программа → тренажёры → инструкторы → шахматки | `replan`, `manual.lock_program`/`lock_resources`, `board_days.lock`. Тренажёры блокируются **все** (`services.lock_equipment`), а не только свои: добор ждущих пересобирает внутри чужие программы с другими тренажёрами уже под блокировкой шахматок. Нарушение — взаимная блокировка |
| Правка с устаревшей версией отклоняется | `Booking.version`, `manual.fresh` |
| Индивидуальные — только в шахматках (сегодня, следующий будний), только по будням | `board_days.drop_beyond_boards`, `is_weekend` |
| В дни поступления и выписки занятий нет | `Program.therapy_dates`, `is_therapy_day` |
| Права — в сервисах, а не в шаблонах | `require_*` в каждом сервисе |
| Автор правки в журнале | `instance._history_user = user` перед `save()` |

Известные ограничения записаны в TZ.md, строка решения 83: архив инструктора и сверка шахматок идут разными транзакциями; первый запрос нового дня создаёт шахматку внутри `replan` уже после блокировки тренажёров — два таких запроса одновременно могут взаимно заблокироваться (PostgreSQL обрывает один).

## 9. Интерфейс: HTMX и скрипты

- На `<body>` — `hx-boost`: переходы без перезагрузки. Ссылки на скачивание файлов и в админку — с `hx-boost="false"`.
- htmx не выполняет `<script>` из ответов (`allowScriptTags: false`): все скрипты подключаются только в `<head>` `base.html` и работают по наличию своих элементов (`board.js` — по `#board`). Версия статики — тег `assets` (`?v=`), чтобы браузер не брал старый скрипт.
- CSRF для HTMX — из cookie (`live.js`).
- Шаблоны — `templates/<app>/<screen>.html`; фрагменты HTMX — с подчёркиванием. Комментарий Django `{# … #}` — **только в одну строку**; многострочный — `{% comment %}`, иначе он виден на странице.
- Страница программы: таблица назначений только для чтения (отменённые свёрнуты), правка — панель справа (`programs/_prescription_panel.html`); действие панели возвращает панель, таблицу и расписание — `hx-swap-oob`. Порядок в карте — перетаскивание (`reorder_prescriptions`).
- Шахматка: клик по ячейке — панель `#cell-panel` (`_board_cell.html`); перетаскивание — `board.js` (`data-drag`, `data-drop`, `data-equipment-drop`); итог — `_board_done.html` + вся шахматка через `hx-swap-oob`. Щелчок по пациенту в таблице тренажёров — панель пометки (`_board_equipment.html`).

## 11. Тесты

- `tests/<app>/` повторяет `apps/`. Около 1300 тестов, полный прогон ~10 минут на настоящем PostgreSQL. Параллельные прогоны — каждому свою базу: `DATABASE_URL=postgres://omr4:omr4@localhost:5432/omr4_<имя> .venv/bin/pytest -p no:cacheprovider`.
- `tests/conftest.py` — общие фикстуры: отделения, пользователи (`make_user("x", (department, Preset.DOCTOR))`), процедуры, вымышленные инструкторы (Волков/Лебедева — 2/2, Соколов — 5/2), `make_program`, `patient`. «Сегодня» в тестах подменяют: `monkeypatch.setattr(board_days, "today", lambda: TUE)`.
- Листы назначений — только из `tests/sheets.py` (вымышленные данные). Персональные данные из `primary_docs/` в тесты не попадают; без `primary_docs/` тесты, которым нужны файлы заказчика, пропускаются.
- Найденная, но ещё не исправленная ошибка — тест с `@pytest.mark.xfail(strict=True, reason=…)`; после исправления метку снимают (иначе XPASS роняет прогон).
- Покрытие `domain/`, `apps/cards/xlsx/`, `exchange/` — не ниже 90 %; для сервисов — ключевые сценарии и права.

## 12. Как вносить изменения

1. Сверьтесь с [TZ.md](TZ.md): есть ли требование или решение. Новое поведение — согласовать с владельцем и записать решение в §13.
2. Правило — в `domain/` (чистый Python) или в `services.py`; права — через `access.py`; вьюха — тонкая.
3. Изменили назначения, курс, группы, тренажёры — убедитесь, что вызывается `replan` (или `replan_for_group` / `replan_for_equipment`).
4. Изменили модель — миграция; удаление в справочниках — по правилу §7.9 (проверка всех FK).
5. Пакетная запись — явный `live.publish`; сохранение с историей — `_history_user`.
6. Тесты рядом с кодом; выгрузки xlsx — читать обратно.
7. Поведение экрана поменялось — правится [user-guide.md](user-guide.md) / [admin-guide.md](admin-guide.md).
8. Перед сдачей: `ruff format . && ruff check .`, `makemigrations --check --dry-run`, `pytest`.
9. Выпуск — тег, тест на копии прода, затем прод ([deploy.md](deploy.md), раздел 12). Коммиты — только по просьбе владельца.
