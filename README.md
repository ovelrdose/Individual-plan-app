# Программа реабилитации — веб-сервис для ОМР № 4

Веб-сервис для отделения медицинской реабилитации. Что он делает:

- создаёт **индивидуальную программу медицинской реабилитации** из листа назначений врача (`.docx` или `.doc`);
- сам ставит пациенту группы ЛФК, группы дневного стационара, бассейн и тренажёры на весь курс;
- ведёт **расписание** индивидуальных занятий с инструкторами на день вперёд (на бумаге его называют «шахматкой») с равномерной нагрузкой на инструкторов;
- выгружает **карту пациента** в `.xlsx` по шаблону для печати из MS Excel. Отметки о проведённых занятиях ставятся на распечатке от руки.

Интеграций с МИС нет. Данные хранятся только на сервере клиники.

## Стек

Python 3.12, Django 5.2 LTS, PostgreSQL 16, шаблоны Django + HTMX + Alpine.js, Bootstrap 5 (без CDN, всё в `static/vendor/`), openpyxl, python-docx, django-simple-history, pytest; для листов `.doc` — LibreOffice на сервере. Точные версии — в `pyproject.toml`.

## Быстрый старт (разработка)

Нужны Python 3.12 (с пакетом `python3.12-venv`) и PostgreSQL 16. Роли базы нужно право `CREATEDB`, иначе pytest не создаст тестовую базу.

```bash
sudo -u postgres psql -c "CREATE ROLE omr4 LOGIN PASSWORD 'omr4' CREATEDB;"
sudo -u postgres psql -c "CREATE DATABASE omr4 OWNER omr4;"

python3 -m venv .venv
.venv/bin/pip install --upgrade pip            # нужен pip ≥ 25.1 для --group
.venv/bin/pip install --group dev
cp .env.example .env                           # поправить SECRET_KEY и DATABASE_URL

.venv/bin/python manage.py migrate
.venv/bin/python manage.py load_initial_catalog   # справочники из primary_docs/
.venv/bin/python manage.py seed_dev               # admin / doctor / rehab (пароль devpass123)
.venv/bin/python manage.py runserver
```

Сервис откроется по адресу http://127.0.0.1:8000/.

## Management-команды

| Команда | Что делает | Повторный запуск |
|---|---|---|
| `load_initial_catalog` | Процедуры, групповые занятия (`lfk.xlsx`, `basseyn.xlsx`, `Gruppy_DS.xlsx`), тренажёры, сетка слотов, отделение ОМР № 4 | безопасен |
| `create_users` | Три пользователя для рабочей установки: врач, специалист ФР, администратор. Пароли спрашивает или берёт из `--password` | существующих не меняет |
| `seed_dev` | Только при `DEBUG=true`: пользователи `admin` / `doctor` / `rehab` с паролем `devpass123` и вымышленные инструкторы | безопасен |
| `load_board_instructors --since ГГГГ-ММ-ДД [--replace]` | Настоящие инструкторы, пары 2/2 и распорядок из `primary_docs/instructions_schedule.xlsx`. С `--replace` удаляет инструкторов, которых нет в файле | безопасен |
| `load_current_patients [--date ГГГГ-ММ-ДД]` | **Удаляет всех пациентов** и заводит текущих по сводкам постов (`primary_docs/Svodka_*.docx`: ФИО, ИБ, возраст, пол, даты поступления и выписки, врач), индивидуальные и тренажёры на дату — как на `primary_docs/planomr4.jpg`. Спрашивает подтверждение | пересобирает заново |
| `extract_card_templates` | Пересобирает шаблоны карт ШРМ 3/4/5 из `primary_docs/programm_template.xlsx` | безопасен |

Запуск: `.venv/bin/python manage.py <команда>`, справка: `… <команда> --help`.

## Настройки

Все настройки лежат в `config/settings.py`, а их значения берутся из `.env` (образец — `.env.example`).

| Переменная | Значение |
|---|---|
| `DEBUG` | `true` только для разработки |
| `SECRET_KEY` | Длинная случайная строка, своя для каждой установки |
| `ALLOWED_HOSTS` | Имена и адреса сервера через запятую |
| `DATABASE_URL` | `postgres://пользователь:пароль@хост:5432/база` |
| `TIME_ZONE` | Часовой пояс клиники, по умолчанию `Europe/Moscow` |
| `SESSION_IDLE_HOURS` | Через сколько часов бездействия сессия завершается (8) |
| `PUBLIC_BOARD_NETWORKS` | Сети, из которых открывается публичное расписание `/board/`. Пусто — доступ отовсюду |
| `CSRF_TRUSTED_ORIGINS`, `BEHIND_PROXY`, `SECURE_HSTS_SECONDS`, `LOG_LEVEL` | Только прод: адрес сайта, работа за nginx, HSTS, уровень журнала — см. `deploy/env.production.example` |

## Тесты и стиль

```bash
.venv/bin/pytest                                         # все тесты, на настоящем PostgreSQL
.venv/bin/pytest --cov=apps --cov-report=term-missing    # с покрытием
.venv/bin/ruff format . && .venv/bin/ruff check .        # перед сдачей — без ошибок
```

В тестах используются только вымышленные данные: листы назначений генерирует `tests/sheets.py`, инструкторов создаёт `seed_dev`. Персональные данные из `primary_docs/` в тесты не попадают. Без каталога `primary_docs/` (его нет в git) тесты, которым нужны справочники и шаблон заказчика, пропускаются, остальные проходят.

## Устройство

```
config/          настройки, корневые адреса
apps/
  org/           отделения
  accounts/      пользователи, права-галочки и отделения, экран «Пользователи», вход с блокировкой, проверка прав (access.py)
  catalog/       процедуры, групповые занятия, тренажёры, сетка слотов
  staff/         инструкторы, пары 2/2, смены, распорядок
  programs/      индивидуальные программы и назначения
  scheduling/    подбор групп и тренажёров (domain/), расписание индивидуальных на день
                 (board.py, board_days.py), групповые занятия, загрузка инструкторов
  exchange/      разбор листа назначений и сопоставление со справочником
  cards/         выгрузка карты и расписания в .xlsx
  live/          обновление страниц в реальном времени (SSE + PostgreSQL NOTIFY)
templates/       шаблоны; фрагменты HTMX — с подчёркиванием
static/          свои стили и скрипты; vendor/ — библиотеки
tests/           тесты, зеркально apps/
deploy/          прод: gunicorn, systemd, nginx, бэкап, образец .env (docs/deploy.md)
primary_docs/    исходные документы заказчика — только для чтения, не в git (есть персональные данные)
```

Доменная логика (`domain/`, `apps/cards/xlsx/`, разбор листа) написана на чистом Python без Django. Права и бизнес-правила проверяются в `services.py`, а представления остаются тонкими. Подробно — в [docs/architecture.md](docs/architecture.md), соглашения — в [CLAUDE.md](CLAUDE.md).

На экране расписание индивидуальных называется **«Расписание»**, а в коде, моделях и комментариях — `board` / «шахматка» (`BoardDay`, `board.py`). Экран групп называется **«Групповые занятия»** (`group_schedule`).

## Статус

Система выпущена и работает в двух контурах — тестовом и рабочем (отдельные ВМ). Готово: программы из листа назначений и обновление из новой версии листа, карта, расписание групп и тренажёров на курс и индивидуальных на день вперёд (с пометками), выбытие, повторный курс, справочники, пользователи и отделения на экранах сервиса, обновление страниц в реальном времени. Установка, выпуск версии и откат — [docs/deploy.md](docs/deploy.md).
